# U03 — `IProjectService` project read + write lanes

**Goal:** add the **five project seams** to `IProjectService` (the four from
the design doc §9.3 — `ListProjectsAsync` / `GetProjectAsync` /
`CreateProjectAsync` / `UpdateProjectAsync` — **plus** the U03-added
`ListProjectsForGoalAsync` the goal detail view needs to list a goal's
projects) + the **`CreateProjectRequest` /
`UpdateProjectRequest`** DTOs (the design doc §9.4), **implement** them in
`ProjectService` (the frozen `IAuthorizationService` path through the
`ProjectToAuditableResource`, the **creator ∪ GlobalAdmin** standing
re-check on the write lanes, the **`GoalId` guard** on create + update, the
ADR 0079 optional-date shape on `StartAt` / `DueAt`, the `AccessAudit`
rows), + the **pinned Core tests** (the design doc §9.6 project pins).
**`dotnet build` clean; all new tests pass.**

**Entry reads:** U02's handoff section (the goal seams + DTOs exist +
`dotnet build` clean); `docs/design/pl-goals-projects-design.md` §9.3–§9.4
(the exact seam + DTO shapes, verbatim — **the source of truth**, especially
the `GoalId` guard prose + the `ClearGoal` shape + the ADR 0079 date shape);
`src/Kumunita.Core/Projects/IProjectService.cs` (the surface after U02 —
the new four seams go in a **new** `// --- PL project lanes (U03) ---`

`src/Kumunita.Core/Projects/ProjectService.cs` (after U02 — the goal-lane

DTOs' XML-doc style the two project DTOs mirror);
`tests/Kumunita.Core.Tests/ProjectServiceTests.cs` (after U02 — the goal
pins' test style the project pins mirror);

precedent — the non-null-applied / null-clears rule the `UpdateProjectAsync`

**Deliverables (3 file edits + test additions):**
- `src/Kumunita.Core/Projects/IProjectService.cs` (edit): the four project
  seams, **verbatim** from the design doc §9.3, in the new
  `// --- PL project lanes (U03) ---` section. Each seam's XML doc is the
  design doc's prose, verbatim (the `GoalId` guard on create + update, the
  `ClearGoal` shape, the ADR 0079 date shape, the standing re-check, the
  `AccessAudit` row shape).
- `src/Kumunita.Core/Projects/ProjectRequests.cs` (edit): the
  `CreateProjectRequest` + `UpdateProjectRequest` sealed records,
  **verbatim** from the design doc §9.4. The `GoalId?` / `Status?` /
  `StartAt?` / `DueAt?` / `ClearGoal` fields with their XML-doc pins
  (the `required string Title` pin, the ADR 0079 date pin, the ADR 0086
  reference).
- `src/Kumunita.Core/Projects/ProjectService.cs` (edit): the four
  implementations —
  - `ListProjectsAsync`: the M5 `ListBoardsAsync` shape — the `!IsDeleted`
    candidate filter, the optional `ComponentId` filter (C-M3·2), the
    **optional `GoalId` filter** (`null` = all, a value = only that goal's
    projects; the **standalone-projects** feed is the `GoalId == null`
    query — the design doc D8 pin), the `CanSeeAsync(Read)` survivor pass
    over `ProjectToAuditableResource`, the `Created`-descending order, the
    paging, the aggregate `AccessAudit` row (`TargetKind = "project"`,
    `visibleCount` / `hiddenCount` — the C-M3·3 shape).
  - `GetProjectAsync`: the M5 `GetBoardAsync` entry-gate shape — the
    `CanAsync(Read)` decision, the 404-vs-403 split (C3), the single
    `AccessAudit` row.
  - `CreateProjectAsync`: the author's choice written verbatim (ADR
    0001-B), the `AuthorId = actorId`, the `Created` stamp; **the
    `GoalId` guard**: when `request.GoalId != null`, load the goal (404
    if absent / soft-deleted), run `CanAsync(Read)` (403 if denied) —
    **before** writing the project; the `project.create` `AccessAudit`
    row (`TargetKind = "project"`).
  - `ListProjectsForGoalAsync`: the **M5 `ListBoardsForTodoAsync` shape**
    (the per-parent list precedent) — load the goal first (404 if absent /
    soft-deleted) + `CanAsync(Read)` (403 if denied), then the goal's
    `!IsDeleted` projects via `GoalId == goalId`, each survivor-checked
    `CanSeeAsync(Read)`, `Created`-descending, the `goal.projects` shape
    (unpaged — the small per-parent list precedent, the M5 lane-per-todo
    list is the same). This is the seam the goal detail view's
    "projects in this goal" section (U06) calls.
  - `UpdateProjectAsync`: the **standing re-check first** (creator ∪
    GlobalAdmin — the ADR 0070 shape, 404 / 403 / soft-deleted → 404);
    the partial update — `Title` / `Description` (a blank
    `Description` → `null`, the ADR 0070 shape), `Status` (non-null
    applied, `null` clears — the C-M5·4 string shape), `StartAt` /
    `DueAt` (the ADR 0079 shape — non-null applied, `null` clears),
    `GoalId` (a non-null value re-associates — **with the `GoalId`
    guard**: load the goal, 404 / 403, **before** writing; `ClearGoal
    = true` → `GoalId = null`, no guard needed); `AuthorId` / `Created`
    preserved, `Modified` stamped on a real change; the `project.update`
    `AccessAudit` row.
- `tests/Kumunita.Core.Tests/ProjectServiceTests.cs` (edit): the project
  pins (the design doc §9.6 project list): `Project_Feed_GoalIdFilter_Narrows`
  / `Project_Feed_GoalIdNull_StandaloneOnly`; `Project_Detail_404Vs403Split`;
  `Project_Create_GoalIdGuard_RefusedWhenGoalDeleted`;
  `Project_Create_GoalIdGuard_RefusedWhenGoalDenied`;
  `Project_Update_ClearGoal_Unassociates`; `Project_Update_StartAtDueAt_OptionalDateShape`;
  `Project_Update_NonCreatorRefused`; `ProjectsForGoal_Goal404Vs403` (the
  goal guard shape on the per-goal list — the `ListBoardsForTodoAsync`
  todo-guard pin's goal-side twin).
