# U04 — the **eight emitters** (the Web-side hooks that call `NotificationService.EmitAsync`)

**Goal:** wire the **eight emitters** — the call sites that
invoke `NotificationService.EmitAsync` at the **eight** hook
points (post-reply, group-post, event-rsvp, report-file,
report-assign, report-resolve, todo-assign, + the
event-reminder-inbox-row complement to M4's email) — so that
each of the **F1–F8** FACES (except F4, which is the M4
§6.4 reminder's inbox-row complement) actually emits a
`Notification` row + a conditional email. **The service is
frozen (U03); this unit only *calls* it, never re-shapes it.**

**Entry reads (≤ 5 files):**
- **`docs/design/m6-notifications-design.md`** — **§6.2**
  (the `EmitAsync` signature — the parameter order: the
  recipient id, the kind constant, the idempotency key, the
  body, the session, the ct), **§6.3** (the **eight**
  idempotency-key shapes — the
  `notification:{kind}:{stable-source-id}` pattern for each
  hook), **§4** (F1–F8 — the eight FACES the emitters serve).
- **`src/Kumunita.Core/Notifications/NotificationService.cs`**
  (authored by U03) — the **frozen** `EmitAsync` signature
  (the exact parameter order + types the call sites must match).
- **`src/Kumunita.Core/Posts/PostService.cs`** (lines 560–630,
  `CreateReplyAsync`) and (lines 1182–1310, `CreateGroupPostAsync`) —
  the **two post hook points**: the post-reply (the reply's
  author is the *sender*, the post's author is the *recipient*;
  the `Post.AuthorId` field is the recipient, the
  `PostReply.AuthorId` is the sender; the idempotency key is
  `notification:post.reply:{replyId}`) and the group-post (the
  group's members are the recipients, the group-post's author
  is the sender; the idempotency key is
  `notification:group.post:{postId}` — one emission *per
  member* of the group, the M4 §6.4 "per-recipient" precedent).
- **`src/Kumunita.Core/Events/EventReminderService.cs`** (lines
  190–215) — the **M4 §6.4 reminder precedent** (the
  `mailer.StageAsync` call shape, the per-recipient
  `Profile.EmailLanguage` resolution — the **F4** complement:
  M6 adds the *inbox row* to M4's existing email, so the
  emitter here calls `EmitAsync` for the `event.reminder`
  kind with the idempotency key
  `notification:event.reminder:{eventId}:{date}` — the M4
  email key `remind:{eventId}:{userId}` is *unchanged*, the
  M6 inbox key is *new*).
- **`src/Kumunita.Core/Moderation/ModerationService.cs`**
  (lines 104–410, `FileReportAsync` / `AssignReportAsync` /
  `ResolveReportAsync`) — the **three report hook points**:
  the report-filed (the content's author is the recipient,
  the reporter is the sender; key
  `notification:report.filed:{reportId}`), the
  report-assigned (the assigned moderator is the recipient,
  the global admin is the sender; key
  `notification:report.assigned:{reportId}`), and the
  report-resolved (the filer *and* the assignee are the
  recipients — **two** emissions per resolve; key
  `notification:report.resolved:{reportId}` for each).

**Deliverables (closed set):**
- **`src/Kumunita.Core/Posts/PostService.cs`** (modified) —
  in `CreateReplyAsync` (after the reply row is stored, before
  the `SaveChangesAsync`), add the **post-reply emitter**:
  call `NotificationService.EmitAsync(recipientId:
  post.AuthorId, kind: NotificationKinds.PostReply,
  idempotencyKey: $"notification:post.reply:{reply.Id}",
  body: <the reply's body, truncated to ~200 chars, the
  ADR 0018 sender-language pin>, session: session, ct:
  default) — the **F1** FACE. The `NotificationService` is
  **constructor-injected** into `PostService` (the
  `IMailerStage` / `IUserInfoService` /
  `IAuthorizationService` / `IDocumentStore` precedent — the
  M5 `ProjectService` ctor shape; the service is *frozen*,
  the ctor *addition* is the emitter's responsibility, not
  the service's).
- **`src/Kumunita.Core/Posts/PostService.cs`** (modified) —
  in `CreateGroupPostAsync` (after the post row is stored,
  before the `SaveChangesAsync`), add the **group-post
  emitter**: for **each member** of the group (the group's
  `MemberIds` list, excluding the post's author), call
  `EmitAsync(recipientId: member, kind:
  NotificationKinds.GroupPost, idempotencyKey:
  $"notification:group.post:{post.Id}:{member}", body:
  <the post's body, truncated, the ADR 0018 pin>, session:
  session, ct: default)` — the **F2** FACE (the per-member
  emission is the M4 §6.4 "per-recipient" precedent — one
  inbox row + one conditional email per member).
- **`src/Kumunita.Core/Events/EventService.cs`** (or

- **`src/Kumunita.Core/Events/EventReminderService.cs`**
  (modified) — in the per-recipient loop (where the M4
  `mailer.StageAsync` call is), **add the inbox-row

  NotificationKinds.EventReminder, idempotencyKey:

  NotificationKinds.ReportResolved, idempotencyKey:
