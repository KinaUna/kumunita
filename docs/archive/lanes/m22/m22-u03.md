### 2. `src/Kumunita.Web/Views/Onboarding/Index.cshtml`

The guided walk-through view (D4), consuming U02's `OnboardingViewModel` +
the `onboarding.*` keys via `<kw-l>`. Mirror the `Locale/Index.cshtml` markup
idiom (the section cards, the `kw-l` usage, the flash/notice placement):

- **`@model OnboardingViewModel`** at the top (the U02 view model).
- **Title + intro** — `<h1><kw-l K="onboarding.title"/></h1>` + the
  `onboarding.intro` paragraph.
- **The step sequence** — a card per step (display name, avatar, language,
  time zone, date format, email language, contact + visibility), each:
  - the step label (`<kw-l K="onboarding.step_*"/>`),
  - the **"set / not set" hint** (the `OnboardingViewModel.Has*` read: a
    small "✓ set" vs "not set yet" state), and
  - the **"Go to this setting" link** (`<kw-l K="onboarding.visit"/>`) into
    the owning surface (the register D3 table: `/profile/edit`, `/profile`,
    `/settings/language`, `/settings/timezone`, `/settings/dateformat`,
    `/settings/language`) — the walk-through **links into** the frozen
    surfaces; it never re-implements a write (D3/C-M22·4).
- **The finish/skip actions** — a `POST` form to `/onboarding/finish`
  (the `<kw-l K="onboarding.finish"/>` button) + a link/form to
  `/onboarding/skip` (the `<kw-l K="onboarding.skip"/>` button) (D4 — both
  route to U01's `CompleteOnboardingAsync`).
- **Razor doctrine (from the repo instructions):** never interpolate a quoted
  attribute string via `@(...)` (Razor HTML-encodes it); put localized labels
  in proper inline elements (`<span>`/`<button>`), not inside `title="…"`;
  a literal `@Model.X` in a rendered URL is an uninterpolated attribute bug —
  use the resolved value. Every string is a `<kw-l K="…"/>` key, never
  hardcoded (C-M22·6).

### 3. The dismissible home/nav banner (D5) — the shared layout / home view

In the **shared layout** (or the home view, whichever already owns the
resident-facing notice area — confirm by reading `_Layout` /
`Views/Home/Index.cshtml`), add a **dismissible banner** that renders **iff**
the signed-in resident's completion read is `null`:

- The banner reads the **owner-scope** completion state (the same
  `GetOnboardingCompletedAsync` / `Profile.OnboardingCompletedAt` read U02
  uses). Render it **only** when that is `null` (the floor — a fresh
  resident sees it) and the visitor is signed in (`@User.Identity.IsAuthenticated`
  guard; the banner is a signed-in-resident affordance).
- **Copy** — the `onboarding.banner.text` line (`<kw-l K="onboarding.banner.text"/>`)
  + the CTA link to `/onboarding` (`<kw-l K="onboarding.banner.action"/>`).
- **Non-blocking (D5/C-M22·5):** the banner is **dismissible** (a hidden
  "close" that sets a per-browser `localStorage`/cookie dismiss flag — the
  codebase's existing dismiss-idiom, if one exists in `_Layout`; otherwise a
  plain CSS/`<details>` dismiss) and **never blocks sign-in**. The completion
  read is the **only** gate — no claim read, no `IsNew` flag (the thin-token
  rule, ADR 0001-B). When `OnboardingCompletedAt` is non-null, the banner is
  **not** rendered.
- **Nav entry** — a small "Setup" nav entry (the `<kw-l K="onboarding.title"/>`
  or a dedicated short label) in the shared top-nav (the `nav.*` block
  convention), present for a `null`-completion resident, linking to
  `/onboarding`. (If U00's design doc locks the nav-entry label as a
  **separate** key, add it to the closed set in Deliverable 1 first — the
  closed set is the single source.)

> **Drift-catch:** if the codebase has an **existing** dismissible-banner or
> "notice" idiom in `_Layout` (e.g. a guest-welcome notice, the
> `account.guest_welcome` precedent), **mirror it** — do not invent a new
> banner mechanism. The *shape* (dismissible, gated on the
> `OnboardingCompletedAt` read, non-blocking, links to `/onboarding`) is
