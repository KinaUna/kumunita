# U06 — the 9 pinned tests (2 Core additive window pins + 7 Web `?view=` engine pins)

**Goal:** implement the **9 pinned tests** from the design doc §6.3. This unit
does **NOT** run the acceptance gate (U07) and does **NOT** touch the design
doc. Because the lane is **zero Core change**, the 2 Core tests
**re-exercise the *existing* `ListInRangeAsync`** with a 1-day and a 7-day
window to **prove C-DWM·1's "the seam is already window-agnostic" claim** —
no new Core code is added.

**Entry reads:**
- `docs/design/events-calendar-dwm-design.md` §6.3 (the **9 test names**,
  exact — the *primary source* for this unit) + §6.2 (the window math the Web
  tests assert against).
- `tests/Kumunita.Core.Tests/EventCalendarSeamTests.cs` (the **existing EV-CAL
  seam tests** — the harness/fixture/assertion shape to mirror for the 2 new
  additive window pins; the lane **appends, does not modify** existing tests).
- `tests/Kumunita.Web.Tests/EventControllerTests.cs` (the **existing EV-CAL
  Web pins** — the NSubstitute setup for `IEventService` / `IUserInfoService`
  / `EffectiveTimezoneResolver` to mirror for the 7 new `?view=` engine pins).
- `src/Kumunita.Web/Controllers/EventController.cs` the `Calendar` action
  (U02's `?view=` engine — the behavior the 7 Web pins assert: per-view
  window + nav-by-view-unit + `Label` + the `month` fallback).
- `tests/Kumunita.Core.Tests/PostgresFixture.cs` (the Core test harness — the
  `PostgresFixture` usage for the 2 additive window pins).

**Deliverables (2 files, both **append-only**):**
- `tests/Kumunita.Core.Tests/EventCalendarSeamTests.cs` — append **2** tests
  (no new Core code; they call the **existing** `ListInRangeAsync`):
  1. `EV_Range_OneDayWindow_OnlyThatDay` — plant 3 events (one on the anchor
     day, one the day before, one the day after); call
     `ListInRangeAsync(dayStartUtc, dayStartUtc + 1d, null, actorId)`; assert
     exactly the anchor-day event is returned (the other two excluded) —
     proves the seam honors an arbitrary 1-day window (C-DWM·1).
  2. `EV_Range_SevenDayWindow_OnlyThoseDays` — plant events inside and outside
     a 7-day window; call `ListInRangeAsync(weekStartUtc, weekStartUtc + 7d,
     null, actorId)`; assert exactly the in-window events are returned —
     proves the seam honors an arbitrary 7-day window (C-DWM·1).
- `tests/Kumunita.Web.Tests/EventControllerTests.cs` — append **7** tests
  (NSubstitute; no Postgres):
  1. `Calendar_DefaultViewIsMonth_BackwardCompat` — no `?view` ⇒ `View ==
     "month"` + the 30-day→calendar-month window + `Label` = the month name
     (C-DWM·8).
  2. `Calendar_ViewDay_WindowIsAnchorDayOnly` — `?view=day` ⇒
     `windowEndUtc − windowStartUtc == 1d` + `WindowDays.Count == 1`
     (C-DWM·3, F1).
  3. `Calendar_ViewWeek_WindowIsAnchorWeek_MondayStart` — `?view=week` with an
     anchor on, e.g., a Thursday ⇒ `WindowDays.Count == 7`, the first day is
     the **Monday** on/before the anchor, `windowEndUtc − windowStartUtc ==
     7d` (C-DWM·3, C-DWM·5, F2).
  4. `Calendar_ViewMonth_WindowIsAnchorCalendarMonth` — `?view=month` ⇒ the
     window spans the anchor's **calendar month** (starts on the 1st, ends on
     the last day) + `WindowDays` covers 5–6 weeks (C-DWM·3, F3).
  5. `Calendar_InvalidViewFallsBackToMonth` — `?view=year` (and `?view=`
     empty) ⇒ `View == "month"` (display fallback, not an error)
     (C-DWM·3, F5).
  6. `Calendar_ViewRidesAlongInPrevNextNavLinks` — `?view=week&from=<anchor>`
     ⇒ the `PrevAnchor`/`NextAnchor` links carry `?view=week` and the anchor
     shifted **±1 week**; the `componentId` filter rides along too (C-DWM·6,
     F6).
  7. `Calendar_Label_IsViewAppropriate` — `?view=day` ⇒ full date; `?view=week`
     ⇒ a `Mon d – Mon d` range; `?view=month` ⇒ a month name + year (C-DWM·3,
     C-DWM·9).
