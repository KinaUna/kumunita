# U02 — `EventCalendarViewModel` additive fields + the `Calendar` action's `?view=` engine (zero Core change)

**Goal:** the lane's only C# — add the 2 additive `EventCalendarViewModel`
fields (+ the `MonthLabel`→`Label` generalization) and implement the `Calendar`
action's `?view=` engine (parse `view`, compute the per-view window + nav-by-
view-unit + the view-appropriate `Label`). **Zero Core change** (C-DWM·1 —
`IEventService` / `EventService` are untouched; `ListInRangeAsync` is called
unchanged).

**Entry reads:**
- `docs/design/events-calendar-dwm-design.md` §6.1 + §6.2 (the exact
  view-model shape + the `Calendar` engine — the **primary source**).
- `src/Kumunita.Web/Models/EventEditorModel.cs` `EventCalendarViewModel`
  (~L359–368; the record to extend) + `EventRow` (~L288–302; confirm
  `StartUtc`/`EndUtc` are already present — they are).
- `src/Kumunita.Web/Controllers/EventController.cs` the `Calendar` action
  (~L? — find `GET /events/calendar`; the existing `from` → local-midnight →
  UTC → `+30d` math, the `PrevAnchor`/`NextAnchor` pre-render, and the
  `EventCalendarViewModel` construction call site to update).
- `src/Kumunita.Core/Events/IEventService.cs` `ListInRangeAsync` (L48;
  **read-only** — confirm the window-agnostic signature; do **not** modify).
- `src/Kumunita.Web/Localization/EffectiveTimezoneResolver.cs` header +
  `GetAsync` (the zone the window math uses — ADR 0019).

**Deliverables (2 files):**
- `src/Kumunita.Web/Models/EventEditorModel.cs` — extend
  `EventCalendarViewModel` with **exactly** the §6.1 shape: add
  `string View = "month"` and `IReadOnlyList<DateTime> WindowDays = null!`,
  and rename `MonthLabel` → `Label`. **No other field added or removed; no
  Core file touched.** (The `EventCalendarViewModel` construction call site
  is the `Calendar` action, U02's other file — so the rename + the new
  fields compile in the same build.)
- `src/Kumunita.Web/Controllers/EventController.cs` — extend the `Calendar`
  action to `Calendar(string? from, string? componentId, string? view)`:
  - parse `view` (`day`/`week`/`month`, default + invalid/out-of-set →
    `"month"` — C-DWM·3);
  - parse `from` (default today in the effective zone) → the **anchor date**;
  - compute the **window** per view (§6.2): day = `+1d`; week = the
    anchor's **Monday** (local) `+7d` (C-DWM·5); month = the anchor's
    **calendar month** (its computed length);
  - build `WindowDays` = the ordered local grid days (day: 1; week: 7 from
    Monday; month: the 5–6 weeks covering the calendar month from the
    Monday on/before the 1st);
  - call `ListInRangeAsync(windowStartUtc, windowEndUtc, componentId,
    actorId)` **unchanged** (C-DWM·1);
  - nav: prev/next = the anchor shifted by the **view's unit** (±1 day / ±1
    week / ±1 month), pre-rendered as plain GET links carrying `?view=` +
    `componentId` (C-DWM·6); today = the zone's today;
  - `Label` = the view-appropriate display string (Day: full date; Week:
    `Mon d – Mon d`; Month: month name + year) in the UI culture;
  - set `View` + `WindowDays` on the view model (the construction call site
    updated here — the §6.1 shape).
