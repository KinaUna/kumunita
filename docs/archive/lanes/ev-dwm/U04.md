# U04 — Week view (7-column time grid, Monday-start) + `client/lib/events-calendar-time.ts`

**Goal:** add the **Week view** — a 7-column (Monday-start) **time-ruler
grid** (hour rows + time-positioned event blocks) — plus the new plain-TS
module `client/lib/events-calendar-time.ts` that positions each event block by
`%` top/height within its day column and flags overlap. **This module is the
one new client dependency surface — and it is plain-TS, tsc-only, zero
libraries** (ADR 0031 / C-DWM·7). The existing `events-calendar.ts` is
**not modified** (Day will reuse this new module; Month keeps the old one).

**Entry reads:**
- `docs/design/events-calendar-dwm-design.md` §3.3 (the time-ruler + block
  positioning shape) + §3.5 (nav/toggle — already in place from U03).
- `src/Kumunita.Web/Views/Event/Calendar.cshtml` (U03's shape — the
  `WindowDays` loop + the toggle + the chip pool; add the **Day/Week branch**
  that renders the time-ruler grid instead of the chip pool when
  `Model.View != "month"`).
- `src/Kumunita.Web/client/lib/events-calendar.ts` (the **pattern to
  mirror** — the overlap `[startUtc, endUtc)` intersection + the `data-start-utc`
  / `data-end-utc` / `data-time-zone` read pattern; the self-wire-at-load +
  `no any` + `no globals` shape).
- `src/Kumunita.Web/client/lib/name-filter.ts` (the self-contained module
  shape to mirror — a sibling plain-TS module in the same folder).
- `src/Kumunita.Web/package.json` + the `tsconfig.json` (confirm the new `.ts`
  file is picked up by the existing `tsc` build — same `client/lib` root).

**Deliverables (3 files):**
- `src/Kumunita.Web/client/lib/events-calendar-time.ts` (new, ~150–250 lines) —
  a self-contained IIFE module (the `events-calendar.ts` shape, tsc-only, no
  deps, no globals, no `any`):
  - **Block positioning:** for each event block (the view ships one block per
    event in the chip pool, carrying `data-start-utc` / `data-end-utc`),
    compute its day column(s) via `Intl.DateTimeFormat` + the `data-time-zone`
    id (the C-EV·5 display-only pattern) and, within each touched day column,
    the **`top%` = `startHourFraction × 100`** and **`height%` =
    `(endFraction − startFraction) × 100`** of that day (clamped to
    `[0, 100]`); set `style.top` / `style.height` on the block;
  - **Multi-day:** one block instance per day-column touched (the same
    `[startUtc, endUtc)` interval rule as Month) — first instance keeps the
    rendered time label, repeats are title-only;
  - **Overlap flag:** the **same** `[startUtc, endUtc)` intersection rule as
    `events-calendar.ts` (O(n²) over the ≤ 30 window is fine) → the
    `event-chip-overlap` class + the `data-overlap-hint`/English-floor
    `title` (C-DWM·4 — client-side display, never an access decision);
  - **Self-wires at load** on the `#events-calendar` root when
    `data-view != "month"` (the view ships `data-view="@Model.View"`); the
    Month path is untouched (it still uses `events-calendar.js`).
- `src/Kumunita.Web/Views/Event/Calendar.cshtml` — add the **Day/Week branch**:
  when `Model.View == "week"` (or `"day"`), render the **time-ruler grid**
  instead of the chip pool — for each `WindowDays` column: an hour-ruler
  column (0–24, rendered server-side via `kw-dt`) + a `.event-block-stack`
  (the absolutely-positioned block host) + a hidden block pool (one block per
  event in `Model.Events`, carrying `data-start-utc` / `data-end-utc` /
  `data-title` / `data-href`); ship `data-view="@Model.View"` on
  `#events-calendar`; include `~/js/lib/events-calendar-time.js` in `@section
  Scripts` (the `events-calendar.js` include stays for Month). The **Month**
  branch (U03) is unchanged.
- `src/Kumunita.Web/wwwroot/css/site.css` — the **time-grid** styles: the
  hour-ruler column (fixed-width time gutter + hour lines), the
  `.event-block` (absolutely positioned, `top`/`height` from the TS, a
  title/time layout, hover), the overlap ring (reuse `event-chip-overlap`),
  and the Day (1-column) vs Week (7-column) column widths.
