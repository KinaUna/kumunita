# M26 U6 — Core: projects (todos, boards, projects, goals) + tests

> **Sealed unit.** One fresh agent, ~32K context window. Self-contained. The
> register (`docs/plans-milestones/plan-m26-sorting.md`) is the
> cross-reference; when the two disagree, **this file wins for what to do**.
> **Exit: build green + the `Project*_*`/`Todo*_*` tests pass.**
> **Precondition:** U3's `SortSpec`/`SortKeys` exist.

## Understanding

This unit adds the **additive `SortSpec? sort = null`** parameter to the
**four project seams** (`ProjectService.ListTodosAsync` / `ListBoardsAsync` /
`ListProjectsAsync` / `ListGoalsAsync`) + the `IProjectService` seams,
applying the projects allowlist (U2 §2.2: `created` default desc, `modified`,
`title`; todos additionally `due`(nulls last)/`priority`/`status`) + the
tie-breaker, and the **pinned Core tests** (U2 §2.5, the `Project*_*`/
`Todo*_*` set). **`null` preserves the current order exactly (C-SORT·2).**

## Rules
- **C-SORT·2** — `null` keeps the current order (all 4 seams:
  `OrderByDescending(Created)`).
- **C-SORT·4** — the `CanSeeAsync` call is **unchanged** (no new audit row).
- **C-SORT·5** — the tie-breaker `.ThenBy(x => x.Id)` is present on every
  non-null sort path; the `due` key places nulls **last** (define the
  null-placement in the comparator).
- **Do not** change the kanban **column** order (named non-decision — the
  card order within a column is content the user sets).
- **Do not** touch the existing filters (assignee/project/blocked — frozen).
- **Do not** change the `HasMore`/paging computation.
