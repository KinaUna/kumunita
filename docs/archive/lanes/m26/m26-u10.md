## Understanding

This unit establishes the **one shared Web sort control** — `SortViewModel` +
the `_Sort` partial (mirroring the M7 `_Pager` partial) + the **pager-carry
rule** (the `sort`+`dir` pairs join the existing `PagedViewModel.FilterParams`
so prev/next preserve the sort, C-SORT·8) — and wires it into **one reference
surface** (the community post feed, `PostsController.Index`) + its view model's
`Sort` field, with the **pinned Web tests** (U2 §2.6, the `CommunityFeed_*`
set). **This unit establishes the pattern U11–U15 copy — do not fork a
per-surface partial.**

## Rules
- **C-SORT·3** — the `?sort=`/`?dir=` → `SortSpec` mapping is Web-only (the
  `SortKeys.Parse` is Core; the query-param read + the `SortViewModel` build
  are Web).
- **One shared control** — the `SortViewModel`/`_Sort` are the **only**
  control; U11–U15 **reuse** them (each surface passes **its own** allowed-key
  `Options`). **Do not** fork a per-surface partial.
- **C-SORT·8** — the `sort`/`dir` pairs join the existing `Pager`'s
  `FilterParams` so prev/next preserve the sort.
- A `null` `Sort` renders nothing (the no-sort pin).
- The existing `Pager`/`HasMore` behavior is **untouched** (only the
  `FilterParams` gain the two pairs).
- **Do not** touch authorization (C-SORT·4).
