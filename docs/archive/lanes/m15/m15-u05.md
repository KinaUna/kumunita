## Goal

D6 + D8 rendered in the UI (the **batch** half):

- **The batch mode on the existing `Translations` view** — a `Mode`
  flag on the **existing** `TranslationEditorViewModel` (`Single`
  default, `Batch` when `?batch=true` — one additive property, D6's
  "one view, two modes"): the same closed key list, **one `text` input
  per row, one "Save all" button** posting `POST
  /admin/languages/{code}/translations/save-all` → the U03
  `SaveAllTranslationsAsync` seam + the one `translation.save_all`
  audit row; a quiet top toggle between the two modes (two `kw-l`
  links, plain `<a>`, no JS); a **blank input is a no-op** (the
  service's rule, C-M15·4 — the batch form never erases a row).
- **The per-row editor stays byte-identical** when the flag is absent
  (C-M15·7) — the `SaveTranslation` route and the per-row form are
  untouched; the batch mode is additive markup gated on the flag.
- **Three `kw-l` keys × en/de/fr/da** (D8, this unit's share):
  `translations.bulk.save_all`, `translations.bulk.mode_batch`,
  `translations.bulk.mode_single`.
- The route rides the **existing** class gate (D3).
- **2 pinned tests** (names verbatim from the design doc).
