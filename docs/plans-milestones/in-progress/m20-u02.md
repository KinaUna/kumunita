## Deliverables (4 files)

### 1. `src/Kumunita.Core/Notifications/NotificationQuietSchedule.cs`

The document + enum, **verbatim** from the design doc §4 (the register's D2
block). The document is a POCO with the `RecipientId` identity (one row per
recipient, the `NotificationPreference` shape): `Enabled` (default `false` =
the "never quiet" floor), `Mode` (`Blocked` = the lean default, the intuitive
"quiet at night" reading), `Hours` (`int[]`, empty = all hours), `DaysOfWeek`
(`int[]`, empty = all days), `Updated?`. `QuietScheduleMode` is the
`Blocked = 0` / `Allowed = 1` enum (D2).

### 2. `src/Kumunita.Core/Notifications/QuietScheduleEvaluator.cs`

A **static, pure** class (the `UsageCapturePolicy` / `IcsWriter`
"pure, closed, testable in isolation" discipline — no session, no HTTP, no IO):

```csharp
public static class QuietScheduleEvaluator
{
    /// <summary>
    /// D3 — pure, timezone-aware "is it quiet now?" Verdict: a <c>null</c>
    /// schedule is never quiet (the floor, C-M20·3). Otherwise the instant is
    /// converted to <paramref name="effectiveZone"/>'s wall clock FIRST (ADR
    /// 0019 — the wall-clock-first order the <c>kw-dt</c> TagHelper +
    /// <c>EventReminderService</c> use), then:
    ///   Blocked mode — quiet iff (Hours empty OR wallHour in Hours) AND
    ///                  (DaysOfWeek empty OR wallDow in DaysOfWeek).
    ///   Allowed mode — the INVERSE: quiet iff NOT (wallHour in Hours OR wallDow
    ///                  in DaysOfWeek) — i.e. the email flows only during a
    ///                  listed hour/day, and is held otherwise (an allowed
    ///                  schedule with both lists empty is "always quiet").
    /// A disabled schedule (<c>Enabled == false</c>) is never quiet regardless
    /// of the mode (the D2 master on/off).
    /// </summary>
    public static bool IsQuietNow(
        NotificationQuietSchedule? schedule,
        DateTimeOffset now,
        TimeZoneInfo effectiveZone);
}
```

Implement the body exactly as described (wall-clock-first; empty-list =
all-of-that-axis in `Blocked`; the `Allowed` inverse; `Enabled == false` →
`false`; `null` → `false`). **Do not** read a session, take a `string`, or
call any service — the caller resolves the effective zone (U03) and passes a
concrete `TimeZoneInfo`.

### 4. `src/Kumunita.Core/Notifications/NotificationService.cs` (two owner-scope seams)

Add two public methods (the `SetProfileTimezoneAsync` single-write-lane shape —
owner scope, **no** `AccessAudit` row, ADR 0019). They are the **only** writes
to the schedule (C-M20·7); a direct `IDocumentSession.Store` from a controller
is forbidden by the design (D2 `*Forbids:*`). The Web boundary (U06) owns the
owner check (signed-in subject == `recipientId`); the Core seam does **not**
re-check `User`.

```csharp
/// <summary>D2 — read the recipient's quiet schedule, or null (= never quiet,
/// the floor). Owner-scope read; no audit row (ADR 0019 personal-preference
/// shape).</summary>
public async Task<NotificationQuietSchedule?> GetQuietScheduleAsync(
    string recipientId, CancellationToken ct = default);

/// <summary>D2 — store-or-update the recipient's quiet schedule; a null
/// schedule clears it (= never quiet). Owner-scope write; no audit row. The
/// Web boundary owns the owner-scope check (C-M20·7).</summary>
public async Task SetQuietScheduleAsync(
    string recipientId, NotificationQuietSchedule? schedule, CancellationToken ct = default);
```

Implement both against `IDocumentStore` (open a session, load-or-store,
`SaveChangesAsync`). Stamp `Updated` on a real write.

## Pinned tests (add to the `Kumunita.Core.Tests` `NotificationService` test file)

- **GATE-2 pin (C-M20·2 — timezone-aware)** — `QuietScheduleEvaluator_IsQuietNow_Is_TzAware`:
  a `Blocked` schedule (e.g. hours `{22,23}`) + the same `DateTimeOffset`
  instant yields **different** verdicts when the effective zone is `UTC+2` vs
  `UTC` (the wall-clock-hour differs; the verdict flips). Assert both.
- **GATE-3 pin (C-M20·3 — floor = never quiet)** —
  `QuietScheduleEvaluator_NullSchedule_Is_Never_Quiet` (and the
  `Enabled == false` case): `null` → `false`; a stored-but-disabled schedule →
  `false`; an enabled empty-list `Blocked` schedule → quiet at any hour.
- **Doc round-trip (C-M20·3/·7)** — `NotificationQuietSchedule_StoreAndLoad_RoundTrips`:
  via a real `IDocumentStore`, `SetQuietScheduleAsync` then `GetQuietScheduleAsync`
  returns the stored row; `SetQuietScheduleAsync(null)` clears it to `null`.
- **Owner-scope, no audit row (C-M20·7)** —
  `SetQuietScheduleAsync_Does_Not_Append_AccessAudit`: a write appends **no**
  `AccessAudit` row (assert the audit log is unchanged after the write).
