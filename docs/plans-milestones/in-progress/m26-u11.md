# M26 U11 — Web: post feeds (all-sections, group) + events (upcoming, past, group) + tests

> **Sealed unit.** One fresh agent, ~32K context window. Self-contained. The
> register (`docs/plans-milestones/plan-m26-sorting.md`) is the
> cross-reference; when the two disagree, **this file wins for what to do**.
> **Exit: build green + the `AllFeed_*`/`GroupPostFeed_*`/`Event*_*` Web
> tests pass.** **Precondition:** U10's `SortViewModel` + `_Sort` exist and
> the U4/U5 Core seams accept `SortSpec?`.

## Understanding

This unit applies the **U10 `_Sort` pattern** to the remaining **post-feed**
surfaces (all-sections feed, group posts) and the **events** surfaces
(upcoming list, past list, group events) — the view-model `Sort` field + the
`@Html.Partial("_Sort", ...)` + the pager-carry + the `SortSpec` threading —
with the **pinned Web tests** (U2 §2.6, the `AllFeed_*`/`GroupPostFeed_*`/
`Event*_*` set). **Reuse U10's `SortViewModel`/`_Sort` verbatim — do not
fork.** Each surface passes **its own** allowed-key `Options` (C-SORT·1/F9).

## Rules
- **Reuse** U10's `SortViewModel`/`_Sort` verbatim (C-SORT·1 — each surface
  passes **its own** allowed-key `Options`).
- **C-SORT·8** — each surface's pager carries **its own** `sort`/`dir`.
- **C-SORT·2** — the `null`/no-sort pin is unchanged (a `null` `Sort` renders
  nothing).
- **C-SORT·4** — authorization is **untouched**.
- **Do not** touch the existing filters (frozen) or the calendar day/week/
  month views (named non-decision).
