# U08 — the **`client/lib/notifications-bell.ts`** module (the bell's 30-second poller + the dropdown render) + the **`site.css`** rules

**Goal:** create
**`src/Kumunita.Web/client/lib/notifications-bell.ts`**
(the **30-second `setInterval` poller** that fetches
`GET /notifications/unread-count`, updates the badge
element's text + `hidden` attribute, and renders the
dropdown's five most-recent notifications as a plain
`fetch` + DOM render) and add the **`site.css`** rules for
the bell badge + the dropdown — the **plain `client/lib`
tsc-only TS** (the ADR 0031 pin — no bundler, no
dependency, no WebSocket, no SSE, no push — the
30-second poll is the *shape*). **The `tsc` build is
green** (the ADR 0031 / the M4 / M5 `client/lib`
precedent — the `npm run build` from
`src/Kumunita.Web` compiles the TS to
`wwwroot/js/lib/notifications-bell.js`).

**Deliverables (closed set):**
- **`src/Kumunita.Web/client/lib/notifications-bell.ts`**
  (new) — the **plain-TS module** (the ADR 0031 pin — no
  import from a *package*, the `client/lib/api.ts`
  fetch-helper is the *only* dependency):
  - **The `bindNotificationsBell()` entry point** (the
    `export function bindNotificationsBell(): void` shape,
    the ADR 0031 module-shape precedent — called from the
    `_AccountNav.cshtml` partial's
    `<script type="module"
    src="~/js/lib/notifications-bell.js"></script>` tag,
    the M4 / M5 `client/lib` script-tag precedent).
  - **The 30-second poller:** a `setInterval` (the
    C-M6·10 pin) calling `fetch('/notifications/unread-count',
    { headers: { 'Accept': 'application/json' } })` (the
    CSRF-aware fetch shape — the `client/lib/api.ts`
    precedent, the `X-CSRFToken` header *not* required for
    a `GET`, the ADR 0031 / the M4 / M5 fetch precedent),
    parsing the `{ "count": N }` JSON, and updating the
    `#notifications-badge` element:
    - **When `count > 0`:** set `badge.textContent =
      count.toString()`, `badge.hidden = false` (the
      badge *shows*).
    - **When `count === 0`:** set `badge.hidden = true`
      (the badge *hides* — the `hidden` attribute, the
      U06 markup shape).
  - **The dropdown render:** on the dropdown's
    `show.bs.dropdown` event (the Bootstrap event, the
    M2/M3/M4 nav-dropdown idiom), `fetch(
    '/notifications', { headers: { 'Accept':
    'text/html' } })` (the inbox view's *HTML*, the
    server-rendered shape — the dropdown renders the
    *first five* `list-group-item` elements from the
    response, the `document.querySelector` +
    `innerHTML` shape, the plain-DOM precedent).
  - **The error handling:** a `try/catch` around the
    `fetch` (the M4 / M5 `client/lib` error-handling
    shape), a `console.warn` on failure (the no-retry
    shape — the 30-second poll is the *shape*, the
    no-retry is the *lean* shape).
  - **The teardown:** a `window.addEventListener(
    'pagehide', ...)` (the SPA-shape, the M4 / M5
    `client/lib` teardown precedent) that calls
    `clearInterval` on the poller's id (the no-leak
    shape).
- **`src/Kumunita.Web/site.css`** (modified) — **add the
  bell badge + dropdown rules** (the ADR 0031 / the
  M4 / M5 `site.css` precedent):
  - **The badge position:**
    `#notifications-badge { top: -0.25rem; right: -0.5rem;
    font-size: 0.625rem; min-width: 1rem; height: 1rem;
    line-height: 1rem; padding: 0 0.25rem; }` (the
    `position-absolute top-0 start-100 translate-middle`
    shape the U06 markup uses, the Bootstrap override
    shape).
  - **The dropdown width:**
    `.notifications-dropdown { width: 320px; max-height:
    400px; overflow-y: auto; }` (the dropdown's
    *fixed* width + *scrollable* height, the M2/M3/M4
    nav-dropdown shape).
  - **The list-item density:**
    `.notifications-dropdown .list-group-item { padding:
    0.5rem 0.75rem; font-size: 0.875rem; }` (the
    *compact* list-item shape, the M5 list-view
    precedent).
- **Nothing else.** No new `.ts` dependency (the ADR 0031
  no-dependency pin holds), no bundler (the `tsc`-only
  pin), no WebSocket / SSE / push (the C-M6·10 no-push
  pin holds), no controller change (U05's routes are
  *untouched*), no tests (U09), no ADR.
