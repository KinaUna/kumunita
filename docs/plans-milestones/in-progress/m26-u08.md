# M26 U8 — Core: tags (posts, pages) + people (by-tag, by-bio) + tests

> **Sealed unit.** One fresh agent, ~32K context window. Self-contained. The

## Understanding

This unit adds the **additive `SortSpec? sort = null`** parameter to the
**four tag/people seams** (`TagService.ListPostsByTagPagedAsync` /
`ListPagesByTagPagedAsync` and `ProfileFindService.FindPeopleByTagAsync` /
`FindPeopleByBioAsync`) + their interfaces, applying the allowlists (U2 §2.2:
tag posts `created`/`modified`/`title`; tag pages `created` **asc**/
`modified`/`title`; people `created`/`name`) + the tie-breaker, and the
**pinned Core tests** (U2 §2.5). **`null` preserves each surface's current
order exactly (C-SORT·2)** — note tag pages' `created`-**asc** is the *current*
order, so preserve it exactly.

## Rules
- **C-SORT·2** — `null` keeps each surface's current order (tag posts desc,
  tag pages **asc**, people their current order) **exactly**.
- **C-SORT·4** — the tag-slug resolve + the people `CanSeeAsync` gate are
  **frozen** (no new audit row, no gate change).
- **C-SORT·5** — the tie-breaker is present on every non-null sort path;
  people's `name` uses `StringComparer.OrdinalIgnoreCase`.
- **Do not** change the `HasMore`/paging computation.
