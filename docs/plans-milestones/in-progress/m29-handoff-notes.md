- **Drift notes (unit-series rule 8 — entry reads reveal the register is mildly out of date, recorded, no silent re-shape):** (1) the design doc §2.3 read-seam pseudocode calls `Translation.GetAsync(fallbackKey, effectiveLanguage)` — there is **no** static `Translation` in Core; the real Core read seam is `ITranslationProvider` (`Kumunita.Core.Localization`, `GetAsync(string key, string? preferredLanguageCode)`). `SurfaceLabelsService` therefore composes `ITranslationProvider` (the `ProjectService`/`EventReminderService` **optional** ctor seam `ITranslationProvider? translations = null`), calls `GetAsync(fallbackKey, effectiveLanguage)`, and degrades to the raw `fallbackKey` string when the provider is null / throws (a direct-construction harness with no provider still resolves a set label — M29·1 holds either way). (2) the register's "two boot paths" is **one** host line: every `*DocTypes.Configure(opts)` call (M1/M3/Media/Page/SITE/Tag/M4/…) lives in the single `AddMarten(opts => {…})` lambda in `src/Kumunita.Web/Program.cs`; `SchemaBootstrap` (Core) has **no** doc-type list — it only runs `ApplyAllConfiguredChangesToDatabaseAsync()` over the already-configured store. So U03 adds **one** `Configure` line (`Program.cs:143`), not two (the SITE precedent's "host line" is the same single `Program.cs` line). U03 ships the host line (unlike SITE, which deferred it to U05) because the M29 register assigns it to U03 and there is no Web view to touch yet.
