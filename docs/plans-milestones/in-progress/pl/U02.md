# U02 — `IProjectService` goal read + write lanes

**Goal:** add the **four goal seams** to `IProjectService` (**verbatim**
from the design doc §9.3 — `ListGoalsAsync` / `GetGoalAsync` /
`CreateGoalAsync` / `UpdateGoalAsync`) + the **`CreateGoalRequest` /
`UpdateGoalRequest`** DTOs (the design doc §9.4), **implement** them in
`ProjectService` (the frozen `IAuthorizationService.CanSeeAsync(Read)` /
`CanAsync(Read)` path through the `ProjectGoalToAuditableResource`, the
**creator ∪ GlobalAdmin** standing re-check on the write lanes, the
`AccessAudit` rows), + the **pinned Core tests** (the design doc §9.6 goal
pins). **`dotnet build` clean; all new tests pass.**

`dotnet build` clean); `docs/design/pl-goals-projects-design.md` §9.3–§9.4

**Deliverables (3 file edits + 1 test addition):**
- `src/Kumunita.Core/Projects/IProjectService.cs` (edit): the four new
  seams, **verbatim** from the design doc §9.3, in a new
  `// --- PL goal lanes (U02) ---` section (after the existing write-lane
  section, **before** any new project section U03 adds — the section order
  is goals → projects → association → delete). Each seam's XML doc is the
  design doc's prose, verbatim (the `CanSeeAsync(Read)` gate, the C3
  404-vs-403 split, the standing re-check, the `AccessAudit` row shape).
- `src/Kumunita.Core/Projects/ProjectRequests.cs` (edit): the
  `CreateGoalRequest` + `UpdateGoalRequest` sealed records, **verbatim**
  from the design doc §9.4, with the XML-doc style mirroring the existing
  records (the `required string Title` pin, the `Description?` blank →
  `null` pin on the update DTO, the ADR 0086 reference).
- `src/Kumunita.Core/Projects/ProjectService.cs` (edit): the four
  implementations —
  - `ListGoalsAsync`: the M5 `ListBoardsAsync` shape, verbatim structure —
    the `!IsDeleted` candidate filter, the optional `ComponentId` filter
    (a filter, never a gate — C-M3·2), the `CanSeeAsync(Read)` survivor
    pass over `ProjectGoalToAuditableResource`, the `Created`-descending
    order, the paging, the aggregate `AccessAudit` row (`TargetKind
    = "goal"`, `visibleCount` / `hiddenCount` — the C-M3·3 shape).
  - `GetGoalAsync`: the M5 `GetBoardAsync` entry-gate shape — the
    `CanAsync(Read)` decision, the `KeyNotFoundException` (404) on
    absent / soft-deleted, the `UnauthorizedAccessException` (403) on
    denied (the C3 split), the single `AccessAudit` row.
  - `CreateGoalAsync`: the author's choice written verbatim (ADR 0001-B —
    the `Audience` / `ComponentId` / `LanguageCode` fields pass through
    untouched), the `AuthorId = actorId`, the `Created` stamp, the
    `goal.create` `AccessAudit` row (`TargetKind = "goal"`).
  - `UpdateGoalAsync`: the **standing re-check first** (creator ∪
    GlobalAdmin — the ADR 0070 shape, `KeyNotFoundException` 404 /
    `UnauthorizedAccessException` 403 / soft-deleted → 404), the full
    update of `Title` + `Description` (a blank `Description` → `null`, the
    ADR 0070 shape), `AuthorId` / `Created` preserved, `Modified` stamped
    on a real change, the `goal.update` `AccessAudit` row.
- `tests/Kumunita.Core.Tests/ProjectServiceTests.cs` (edit): the goal
  pins (the design doc §9.6 goal list), mirroring the M5 pin style:

  `Goal_Update_CreatorHasStanding` / `Goal_Update_NonCreatorRefused`

  0070 shape).
