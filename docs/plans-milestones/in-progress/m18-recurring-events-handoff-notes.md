## U04 — Head-edit cascade

- **Built:** `UpdateEventRequest.Recurrence: EventRecurrenceRule?` field (D1/D2/D4, GATE-4 — the `CreateEventRequest.Recurrence` field is U02's, unchanged); the D4 cascade branch in `EventService.cs` `UpdateAsync` (signature **unchanged** — the request record carries the new field). GATE-4 tests in new `tests/Kumunita.Core.Tests/EventServiceCascadeTests.cs`.
- **Cascade behavior:** a head edit (the row whose `RecurrenceRule` is non-null, D3) **always** cascades `Title`/`Body`/`Location`/`Capacity`/`Color`/`Audience`/`ReminderEnabled`/`LanguageCode` to every non-deleted sibling (`RecurrenceHeadId == head.Id && IsDeleted == false`) in the **same transaction** (one `SaveChangesAsync`, F4). A **rule** change (`Recurrence`/`Interval`/`Count`/`Ends` differ) **or** a head `Start`/`End` change **re-materializes**: soft-delete the old non-head siblings (`IsDeleted = true`, C-M18·8 — reversible, never hard-deleted), re-expand via the pure U01 expander (`now` = `DateTimeOffset.UtcNow`), insert the new set with fresh `Guid` ids. The head's `Id` is **stable** (updated in place, D4 — never reassigned). A "stop repeating" edit (`Recurrence` null/None) clears the head's `RecurrenceRule` to null + soft-deletes all siblings, leaves no new set.
- **DEVIATION (note for U00/design-owner + U05/U06):** (a) the head's `RecurrenceRule` is **reassigned** on every head edit (to the new rule or null) — the design doc §6 prose says "the head's `RecurrenceRule` is updated to `request.Recurrence` (or cleared if `request.Recurrence` is `null` / `None` — a "stop repeating" edit)"; the shipped code sets `existing.RecurrenceRule = newRule` where `newRule` normalizes `Recurrence.None` → `null`. (b) A non-head row's `UpdateAsync` call still goes through the **existing** single-row edit path (byte-for-byte unchanged — the zero-change branch); the §drift-guard's D4 "no per-occurrence override surface" is enforced at the Web layer (F1 picker disabled on non-head), not the service. (c) `session.Query<Event>()` + in-place POCO mutation requires an explicit `session.Store(sib)` for each sibling — Marten does not auto-persist query-loaded POCO mutations (this bit me on the first run — the tests were failing with stale values until I added the `Store` calls). U05 (Web composer) + U06 (detail page) should surface the head-edit cascade as a single edit action; the skip/undelete buttons (U03) are orthogonal.
