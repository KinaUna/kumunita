# M24 U3 — The two `IMediaFileStore` read-only ADDs + the `LocalVolumeFileStore` impl

> **Sealed unit.** One fresh agent, ~32K context window. Self-contained. The
> register (`docs/plans-milestones/plan-m24-storage-metrics.md`) is the
> cross-reference; when the two disagree, **this file wins for what to do**.
> **Exit: build green.** **Precondition:** U2's design doc Part 2 exists
> (the exact C# shapes in §2.1/§2.2). **No Core service, no Web, no test**
> in this unit — the Core tests are U4; the Web is U5+.

## Understanding

This unit adds the **two read-only** `IMediaFileStore` ADDs
(`GetTotalSpaceBytesAsync` + `GetFreeSpaceBytesAsync`) + implements them in
`LocalVolumeFileStore` (the `DriveInfo` / `statvfs` fallback). **No other
`IMediaFileStore` member is touched** (C-SM·1). **`IMediaStore` is
untouched** (C-SM·1). **`MediaObject` is untouched** (C-SM·1). The impl is
**read-only + no I/O side-effect beyond the statvfs / DriveInfo call**
(C-SM·2).

**The `statvfs` fallback (Linux):** the `LocalVolumeFileStore` already
works on Linux (the `Dockerfile` runs the app in a Linux container). The
`DriveInfo` API is **Windows-only** — on Linux, the `statvfs` syscall
returns the disk-partition total + free bytes. The impl branches on
`OperatingSystem.IsWindows()` and calls `DriveInfo` on Windows,
`statvfs` on Linux. The `statvfs` P/Invoke is a **single
`[DllImport]`** (or a `System.IO` extension if .NET 10 provides one —
check the BCL first; .NET 10 may have a cross-platform `DriveInfo`
replacement, and the unit should prefer the BCL over a P/Invoke if it
exists).

## Deliverables (2 files, modified)

1. **`src/Kumunita.Core/Media/IMediaFileStore.cs`** — append the two
   **read-only** ADDs (C-SM·2; ADR 0006-E lane):
   ```csharp
   /// <summary>The disk-partition total bytes (a `DriveInfo` / `statvfs` read; not a `QuerySession`). M24, ADR 0134 C-SM·2.</summary>
   Task<long> GetTotalSpaceBytesAsync(CancellationToken ct = default);
   /// <summary>The disk-partition free bytes (a `DriveInfo` / `statvfs` read; not a `QuerySession`). M24, ADR 0134 C-SM·2.</summary>
   Task<long> GetFreeSpaceBytesAsync(CancellationToken ct = default);
   ```

2. **`src/Kumunita.Core/Media/LocalVolumeFileStore.cs`** — implement the
   two ADDs (the `DriveInfo` / `statvfs` fallback; C-SM·2). The impl
   branches on `OperatingSystem.IsWindows()`:
   - **Windows:** `DriveInfo.GetDriveFromPath(RootPath).TotalSize` /
     `.AvailableFreeSpace`.
   - **Linux:** a `statvfs` P/Invoke (or the BCL equivalent if .NET 10
     provides one — check the BCL first). The P/Invoke shape:
     ```csharp
     [StructLayout(LayoutKind.Sequential)]
     private struct statvfs_t {
         public ulong f_bsize, f_frsize, f_blocks, f_bfree, f_bavail,
                      f_files, f_ffree, f_favail, f_flag, f_namemax;
     }
     [DllImport("libc", SetLastError = true)]
     private static extern int statvfs(string path, out statvfs_t buf);
     ```
     `GetTotalSpaceBytesAsync` → `(long)(buf.f_blocks * buf.f_frsize)`;
     `GetFreeSpaceBytesAsync` → `(long)(buf.f_bavail * buf.f_frsize)`.
   - **The impl is read-only + no I/O side-effect beyond the statvfs /
     DriveInfo call** (C-SM·2). **No `Directory.CreateDirectory`, no
     `File.Exists`, no other I/O** — just the stat call.

## Rules

- **`IMediaStore` is untouched** (C-SM·1) — the `IMediaStore` interface
  (the *catalog* seam) is **frozen** for M24; U3 only touches
  `IMediaFileStore` (the *volume* seam).
- **`MediaObject` is untouched** (C-SM·1) — the `MediaObject` doc is **not
  reshaped** by M24.
- **Read-only, zero writes** (C-SM·2) — the two ADDs are **reads**; they
  emit **zero** writes, **zero** `AccessAudit` rows, **zero** new
  documents.
- **No Core service, no Web, no test** in this unit (the Core tests are
  U4; the Web is U5+).
