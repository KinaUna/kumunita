# M23 · U02 — `UpsertProfileAsync` write-lane extension (bio verbatim + tag create-or-get)

**You are the U02 agent.** This is a **Core** unit. It extends the **existing**
`IUserInfoService.UpsertProfileAsync` / `UserInfoService.UpsertProfileAsync`
lane so it writes `Profile.Bio` (verbatim) and resolves `ProfileUpdate.TagIds`
to `Tag.Id` values via the **inlined** ADR 0044 create-or-get — one
`tag.create` row per newly created tag, **no** profile-write audit row (the
existing "a Profile field write, not an access decision" shape), all in the
caller's session, one `SaveChangesAsync`. It does **not** touch the two `Profile`
fields (U01 already added them), create `IProfileFindService` (U03), or the Web
editor (U04). **Exit: `dotnet build Kumunita.slnx -c Debug` clean +
`Kumunita.Core.Tests` green.**

**Read the design doc first** — it locks the C# in this unit (D3, C-M23·3,
C-M23·6). If the design doc's §2.3 C# differs from anything you find in the
codebase, **the codebase wins for mechanics** (naming, file layout, the
`AccessAudit` member names, the `SessionOptions`/`store` shape) and the design
doc wins for the **locked surface** (bio verbatim, create-or-get, no
profile-write audit row, one `SaveChangesAsync`, the `CreatedBy` = actor shape).

## Goal

Make the single F13 profile write lane (D3) carry the two new fields:
`Profile.Bio` written **verbatim** (the author's choice is absolute — ADR
0001-B; a `null` patch leaves it), and `ProfileUpdate.TagIds` resolved to
`Tag.Id` values (a missing `Slug` **creates** a `Tag` + one `tag.create` row;
a present `Slug` is **reused**, no row) — **no** new `IUserInfoService` write
method, **no** new `ITagService` profile method, **no** profile-write audit
row, **zero new authorization surface** (C-M23·2), all in the caller's session
(C3).

/// Upsert the profile (the F13 single write lane, extended by M23 / ADR 0123
/// D3). <paramref name="patch"/>'s non-null fields take priority; a null
/// field leaves the current value (the "null ⇒ don't touch" rule). M23 (D3):

### 2. `src/Kumunita.Core/UserInfo/UserInfoService.cs` — implementation extension

In `UpsertProfileAsync`, **after the existing "patch wins on every non-null
field" block** (the `if (patch.Address is not null) …` line), add the two
fields + the tag create-or-get. The whole method body keeps its **one
`SaveChangesAsync`**, its **load-or-create** shape, and its **no profile-write
audit row** comment:

```csharp
public async Task UpsertProfileAsync(Profile profile, ProfileUpdate patch, string? actorBy = null)
{
    var subjectId = profile.SubjectId;

    await using var session = store.OpenSession(new SessionOptions());
    var existing = await session.LoadAsync<Profile>(subjectId).ConfigureAwait(false);

    var doc = existing ?? new Profile
    {
        SubjectId = subjectId,
        ExternalId = profile.ExternalId,
        HouseholdId = profile.HouseholdId,
        DisplayName = profile.DisplayName,
        Verified = profile.Verified,
        Visibility = profile.Visibility,
        ContactVisibility = profile.ContactVisibility,
        Email = profile.Email,
        Phone = profile.Phone,
        Address = profile.Address,
        Bio = profile.Bio,
        TagIds = profile.TagIds,
    };

    // Patch wins on every non-null field; a null field leaves the current value untouched.
    if (patch.DisplayName is not null) doc.DisplayName = patch.DisplayName;
    if (patch.Email is not null) doc.Email = patch.Email;
    if (patch.Phone is not null) doc.Phone = patch.Phone;
    if (patch.Visibility is not null) doc.Visibility = patch.Visibility;
    if (patch.ContactVisibility is not null) doc.ContactVisibility = patch.ContactVisibility;
    if (patch.Address is not null) doc.Address = patch.Address;
    if (patch.Bio is not null) doc.Bio = patch.Bio;   // M23 (D3): verbatim (ADR 0001-B); null ⇒ don't touch

    // M23 (D3): resolve the profile's author-set tags to Tag.Id values — the inlined
    // ADR 0044 create-or-get (TagService.AttachToPostAsync shape). A missing Slug creates
    // a Tag (+ one tag.create row, C-TG·9); a present Slug is reused (no row, C-TG·4).
    // The profile write itself emits no audit row (a Profile field write, not an access
    // decision — the existing shape above). The actor id for any new Tag.CreatedBy is the
    // acting resident (the self-edit standing, D3) — falls back to the owner.
    if (patch.TagIds is not null)
    {
        var now = DateTimeOffset.UtcNow;
        var creator = actorBy ?? subjectId;
        var resolved = new List<string>(patch.TagIds.Count);
        foreach (var raw in patch.TagIds)
        {
            var slug = raw.Trim().ToLowerInvariant();        // DeriveSlug (C-TG·4), the TagService idiom
            if (slug.Length == 0) continue;
            var existingTag = await session.Query<Kumunita.Core.Tags.Tag>()
                .Where(t => t.Slug == slug)
                .FirstOrDefaultAsync();
            if (existingTag is not null)
            {
                resolved.Add(existingTag.Id);                // reuse — no row (C-TG·4)
            }
            else
            {
                var tag = new Kumunita.Core.Tags.Tag
                {
                    Id = Guid.NewGuid().ToString("N"),
                    Slug = slug,
                    Name = slug,
                    LanguageCode = "en",
                    CreatedBy = creator,
                    Created = now,
                };
                session.Store(new Authorization.AccessAudit
                {
                    Id = Guid.NewGuid().ToString("N"),
                    At = now,
                    ActorId = creator,
                    EffectivePrincipalId = creator,
                    Action = "tag.create",
                    TargetKind = "tag",
                    TargetId = tag.Id,
                    Via = Authorization.AccessVia.Owner,
                    Outcome = Authorization.AccessOutcome.Allow,
                });
                session.Store(tag);
                resolved.Add(tag.Id);                         // one tag.create row (C-TG·9)
            }
        }
        doc.TagIds = resolved.ToArray();
    }

    session.Store(doc);
    await session.SaveChangesAsync().ConfigureAwait(false);   // one SaveChangesAsync (C3)
}
```

> **Match the real codebase exactly where it differs:** the `Tag` namespace
> qualification (it may be imported as `using Kumunita.Core.Tags;` — prefer an
> unqualified `Tag` if a `using` is present, mirroring `TagService.cs`), the
> `AccessAudit` member names (read `AccessAudit.cs` and match), the
> `AccessVia.Owner` value (the TG lane's `ResolveAttachVia` — for a profile
> self-edit the via is `Owner`; confirm against the TG lane's `tag.create`
> row's `Via`). The `DeriveSlug` shape is `Trim().ToLowerInvariant()` (read
> `TagService.DeriveSlug`, line ~700, and copy its exact body — if it does
> more than lowercase+trim, copy that). **The bio is written verbatim** (no
> Markdown processing in Core — the `MarkdownRenderer` is a Web-side render,
> U04/U05's). **There is no `tag.attach` row here** (the profile is the
> attaching object; `Profile.TagIds` is the reference — the one `tag.create`
> row per *new* tag is the TG-lane audit; the attach itself is the profile
> write, which has no audit row).

## Tests (Core)

Add/extend the `Kumunita.Core.Tests` profile write-lane test (the existing
profile / `UserInfo` test file):

- **Bio verbatim.** `UpsertProfileAsync` with `patch.Bio = "# hi\n\n*there*"`
  (rich content) → the stored `Profile.Bio` is **byte-for-byte** that string
  (no Core-side Markdown processing). (C-M23·3, GATE-3.)
- **`null` ⇒ don't-touch.** A second `UpsertProfileAsync` with `patch.Bio =
  null` and `patch.TagIds = null` leaves the existing `Bio`/`TagIds`
  untouched. (The patch rule, C-M23·3.)
- **Tag create-or-get — new tag.** `patch.TagIds = ["SOLAR PANELS"]` (a fresh
  slug) → a `Tag` with `Slug = "solar panels"`, `Name = "solar panels"`,
  `CreatedBy = <the actor>` is created, `Profile.TagIds` contains its `Id`,
  and **exactly one** `tag.create` `AccessAudit` row (`TargetKind = "tag"`,
  `TargetId = the tag's Id`) is written. (C-M23·3, C-TG·9, GATE-3.)
- **Tag create-or-get — reuse.** A second `patch.TagIds = ["solar panels"]`
  (the same slug, now present) → the existing `Tag` is **reused** (no new
  `Tag`, no new `tag.create` row). (C-TG·4, C-M23·3.)
- **No profile-write audit row.** After an `UpsertProfileAsync` that only
  changes `Bio`/`TagIds` (no new tags), assert there is **no** `AccessAudit`
  row whose `Action` is a profile-write action (the only rows, if any, are
  `tag.create` rows from newly created tags). (C-M23·3, GATE-3.)
- **Zero new authorization surface.** Assert `ProfileToAuditableResource` is
  unchanged (the two existing adapters carry everything — C-M23·2, GATE-4); a
  pin test that the `IAuthorizationService` surface is unchanged. (GATE-4.)

## What this unit must NOT do (the §drift-guard)

- **Must not** add a **new** `IUserInfoService` write method for profile
  bio/tags — D3 / C-M23·3 forbids it (the bio + tags ride the **single** F13
  `UpsertProfileAsync` lane).
- **Must not** add a **new** `ITagService` profile method (e.g. an
  `AttachToProfileAsync`) — the create-or-get is **inlined** in
  `UserInfoService` (D3's pin); the `ITagService` is **reused, not extended**
  (C-M23·2, D7).
- **Must not** create a second `Tag` doc type for profiles, a `ProfileBio` /
  `ProfileTag` document, or a new `*DocTypes` surface — D1 / C-M23·6 forbids it
  (the `Tag` is the frozen ADR 0044 shared doc; the bio is a field on the
  `Profile`).
- **Must not** emit a **profile-write** `AccessAudit` row — the existing
  `UpsertProfileAsync` shape is "a Profile field write, not an access
  decision"; the **only** audit rows are the **frozen TG-lane** `tag.create`
  rows, one per newly created tag (C-TG·9).
- **Must not** add a new `AccessAction` / `Decide()` branch / `AccessVia` value
  beyond the TG lane's `Owner` (the profile self-edit is `Owner`; the TG lane
  composes only `Owner`/`Admin`) / `IAuthorizationService` method / `TargetKind`
  — C-M23·2 / D7 forbids it.
- **Must not** do any Markdown processing in Core — the bio is stored
  **verbatim**; the `MarkdownRenderer` render is a Web-side concern (U04/U05,
  D5).
- **Must not** create a separate "profile tag editor" controller, or touch the
  Web project — the editor is **U04's** (D3).
- **Must not** change the existing `UpsertProfileAsync` positional param order
  or types — only **append** the optional `actorBy` param (the ADR 0006-E
  compatible lane).
