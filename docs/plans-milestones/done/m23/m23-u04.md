# M23 · U04 — the editor (bio + tags on `ProfileEditViewModel`) + the
directory-detail bio/tags gate + the U04 kw-l keys

**You are the U04 agent.** You are the **Web** unit of milestone **M23 —
Extended user profiles (a biography + free author-set tags)**. U00–U03 are
done and frozen: the two additive `Profile` fields (`Bio`, `TagIds`, U01), the
extended `ProfileUpdate` record + the optional trailing `actorBy` parameter
(U02), and the write-side extension to `UpsertProfileAsync` (bio written
verbatim, tags resolved by slug via the ADR 0044 create-or-get loop with one
`tag.create` `AccessAudit` row per new tag, no separate profile-write audit

(U03). Your unit wires the **Web** surface: the editor (`ProfileEditViewModel`
+ `ProfileController.Edit`) so a resident can set their own bio (rich content)
and tags, and the **directory-detail gate** so a viewer sees another
resident's bio + tags **only** when their `Profile.Visibility` audience admits
them (the design doc §2.5, the D2/D6/C-M23·1/C-M23·4 pin), and authors the
**U04 kw-l keys**.

### 1. `src/Kumunita.Web/Models/ProfileEditViewModel.cs` — the two new fields

Add the M23 fields (the design doc §2.1/D5 editor shape: bio is **rich
content** — the `MarkdownRenderer` render path on display, the WYSIWYG
`bindRichEditor` on edit; tags is the ADR 0044 tag-input string):

```csharp
    // ── M23 (ADR 0123 D1/D5): the extended-profile editor fields ──
    /// <summary>M23 (ADR 0123 D5) — the resident's bio: **rich content** (the
    /// <c>MarkdownRenderer</c> render path on display, the WYSIWYG
    /// <c>bindRichEditor</c> on edit). Stored verbatim (D3); null/blank is
    /// "no bio" (rendered as absent, the M22 "no bio block" shape).</summary>
    [Display(Name = "Bio (rich content)")]   // the <kw-l> key, see Deliverable 3
    public string? Bio { get; set; }

    /// <summary>M23 (ADR 0123 D1/D5) — the resident's free tags, as the
    /// ADR 0044 tag-input editor string (comma/space-separated slugs, the
    /// `TagService` create-or-get shape). Mapped to the U02
    /// <c>ProfileUpdate.TagIds</c> (the resolved slugs) in
    /// <see cref="ToProfileUpdate"/> (C-M23·6: the match is the tag
    /// itself; the tag is a label, never a gate — C-TG·1).</summary>
    [Display(Name = "Tags (skills, interests, knowledge, expertise)")]
    public string? Tags { get; set; }
```

And extend `ToProfileUpdate` to pass the two new `ProfileUpdate` fields (the
U02 extension — `Bio` verbatim, `TagIds` = the parsed slugs, the ADR 0044
`DeriveSlug` shape — lowercase + trimmed, de-duplicated):

```csharp
        // M23 (ADR 0123 D1/D3/D5) — the two extended-profile fields:
        //   • Bio  — written VERBATIM (D3); a blank string is treated as
        //     "no bio" (null) so the display layer's "no bio block" (the M22
        //     "absent" shape) is the canonical no-bio state.
        //   • TagIds — the ADR 0044 tag-input string parsed to slugs
        //     (lowercase + trimmed, de-duplicated — the TagService.DeriveSlug
        //     idiom); the U02 write lane resolves each slug via the create-or-
        //     get loop (one tag.create row per new tag, C-TG·9).
        //     null ⇒ the field is untouched (the "null ⇒ don't touch" patch
        //     rule, the ProfileUpdate idiom).
        Bio: string.IsNullOrWhiteSpace(Bio) ? null : Bio.Trim(),
        TagIds: string.IsNullOrWhiteSpace(Tags)
            ? null
            : Tags.Split(new[] { ',', ' ' }, StringSplitOptions.RemoveEmptyEntries)
                  .Select(s => s.Trim().ToLowerInvariant())
                  .Where(s => s.Length > 0 && s.Length <= 64)   // C-TG·4 slug shape
                  .Distinct()
                  .ToArray(),
```

## Tests (Web)

- **The editor binds the two new fields (D5, C-M23·6).** A POST to
  `/profile/edit` with a bio + a tags string updates the profile's `Bio`
  (verbatim) and `TagIds` (the resolved slugs). A blank bio → `Bio = null`
  (the "no bio block" shape). A blank tags string → `TagIds = null` (the
  "null ⇒ don't touch" patch rule).
- **The edit action passes the viewer's subject as the `actorBy` (D3,
  C-TG·9).** A new tag created by the edit action has `CreatedBy` = the
  viewer's subject id (the C-TG·9 provenance pin).
- **The directory-detail gate (F6 / §2.5, D2/D6).** Seed a profile whose
  `Visibility` admits viewer A and denies viewer B, with a bio + tags. Viewer
  A's `/directory/[subjectId]` shows the bio + tags; viewer B's shows the
  name + verified badge but **no** bio/tags (the F2/D2 gate). (C-M23·4.)
- **The self-view short-circuit (F3).** The profile owner's
  `/directory/[subjectId]` shows their own bio + tags even when their
  `Visibility` excludes everyone else (the F3 pin — no `CanAsync`, no row).
- **The contact block is independent (F2, "two gates").** A profile whose
  `ContactVisibility` admits viewer A but whose `Visibility` denies viewer A
  (or vice versa) — the contact block and the bio/tags are gated
  **independently**; admitting one does not admit the other. (The F2 "two
  independent gates, zero new audiences" pin.)
- **The U04 kw-l keys are non-empty in all four languages (the §key table
  pin).** A parity test asserting each of the seven keys is non-empty in
  en/de/fr/da (the `KwLRegistryConsistencyTests` +
  `KnownTranslationKeys_ParityTests` gate).
- **Zero new authorization surface (GATE-4, C-M23·2, D7).** A pin test
  asserting `IAuthorizationService`'s surface is unchanged (no new method)
  and `ClaimTypes.All` is unchanged.
