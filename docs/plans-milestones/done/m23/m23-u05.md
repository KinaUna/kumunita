### 1. `src/Kumunita.Web/Controllers/FindPeopleController.cs`

The `/people` controller (the D4/D6/F6 pin, the `DirectoryController` shape):

```csharp
using Kumunita.Core.UserInfo;
using Kumunita.Web.Models;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;

namespace Kumunita.Web.Controllers;

/// <summary>
/// M23 (ADR 0123 D4/D6/F6) — the "find people with something in common"
/// surface: the by-tag + by-bio finds over the **actor-visible** resident set
/// (the D6 privacy-pin, the ADR 0044 D5 pin carried to profiles). A match is a
/// **feed organizer, never a gate** (D6) — the gate is the frozen
/// <c>ProfileToAuditableResource</c> + <c>CanSeeAsync</c> (the U03
/// composition service, the M3 ListFeedAsync shape; zero new authorization
/// surface, C-M23·2/D7). Requires sign-in ([Authorize]) — the find is over
/// "who may this actor see," so there is no anonymous find (the F6 pin).
/// </summary>
[Authorize]
[Route("people")]
public sealed class FindPeopleController(IProfileFindService find) : Controller
{
    private static string? SubjectId(System.Security.Claims.ClaimsPrincipal user) =>
        KumunitaPrincipal.SubjectId(user);

    /// <summary>
    /// M23 (ADR 0123 D4/F6) — the find-people index: the two find forms
    /// (by-tag + by-bio) + the results. A blank query / a missing tag returns
    /// the empty state (the U03 "no decision, no row" shape) — no 404, no
    /// error (the D6 "a match is a feed organizer" pin — an empty result is a
    /// valid result).
    /// </summary>
    [HttpGet]
    public async Task<IActionResult> Index(
        [FromQuery] string? bio = null,
        [FromQuery] int page = 1)
    {
        var viewer = SubjectId(User) ?? string.Empty;
        if (!string.IsNullOrWhiteSpace(bio))
        {
            var result = await find.FindPeopleByBioAsync(bio, viewer, page);
            return View("Bio", new FindPeopleBioViewModel(bio.Trim(), result, page));
        }
        // The default index: the two find forms (no results yet).
        return View(new FindPeopleIndexViewModel());
    }

    /// <summary>
    /// M23 (ADR 0123 D4/D6) — the by-tag find: the actor-visible profiles whose
    /// <c>TagIds</c> contain the tag resolved from <paramref name="slug"/> (the
    /// C-TG·4 business-key slug, the U03 resolve), paged (the ADR 0090 D6
    /// <c>HasMore</c> idiom, <c>PageSize = 30</c>). A missing tag returns the
    /// empty state (the U03 "no row" shape). The gate is the frozen
    /// <c>CanSeeAsync</c> (the U03 composition service, one aggregate audit
    /// row, the M3 C-M3·3 lane) — zero new authorization surface (C-M23·2, D7).
    /// </summary>
    [HttpGet("tag/{slug}")]
    public async Task<IActionResult> ByTag(
        [FromRoute] string slug,
        [FromQuery] int page = 1)
    {
        var viewer = SubjectId(User) ?? string.Empty;
        var result = await find.FindPeopleByTagAsync(slug, viewer, page);
        return View("Tag", new FindPeopleTagViewModel(slug, result, page));
    }
}
```

## Tests (Web)

- **The by-tag find returns the actor-visible matched profiles (D4/D6,
  GATE-2).** A signed-in viewer's `GET /people/tag/{slug}` returns only the
  `Visibility`-admitted profiles whose `TagIds` contain the tag; a denied
  profile never surfaces and its tag is not a match artifact. (C-M23·4, D6.)
- **The by-bio find returns the actor-visible matched profiles (D4/D6,
  GATE-2).** A signed-in viewer's `GET /people?bio={q}` returns only the
  `Visibility`-admitted profiles whose `Bio` contains the query. (C-M23·4,
  D6.)
- **The empty state (D4, F6).** A `GET /people?bio=   ` (blank) and a
  `GET /people/tag/definitely-not-a-tag` both return the empty state view
  (the `profile.find.empty` key, no 404, no error) — the U03 "no decision,
  no row" shape. (D6, C-M23·4.)
- **The paging (the ADR 0090 D6 idiom).** Seed >30 visible profiles matching
  the query; `GET /people?bio={q}&page=1` returns 30 with a "Next page"
  link; `&page=2` returns the rest with no "Next page" link. (D4.)
- **The nav entry (F6).** The `_Layout.cshtml` dropdown contains a `People`
  item linking to `/people` with the `nav.people` kw-l key (a non-empty value
  in the current language). (F6.)
- **The U05 kw-l keys are non-empty in all four languages (the §key table
  pin).** A parity test asserting each of the six keys is non-empty in
  en/de/fr/da (the `KwLRegistryConsistencyTests` +
  `KnownTranslationKeys_ParityTests` gate).
- **The find requires sign-in (F6, [Authorize]).** An anonymous `GET
  /people` redirects to the cookie login (the `[Authorize]` pin — no
  anonymous find). (F6.)
- **Zero new authorization surface (GATE-4, C-M23·2, D7).** A pin test
  asserting `IAuthorizationService`'s surface is unchanged (no new method)
  and `ClaimTypes.All` is unchanged. (C-M23·2, D7.)
