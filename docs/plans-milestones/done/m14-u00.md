## Goal

M14's scope (the register's Understanding, locked): the **two coordination
surfaces interlock** — the Events (M4) and Projects (M5) surfaces, which a
neighborhood uses as one thing, now link:

1. **The data interlock (D1–D3).** A to-do can be **associated with an
   event**: one additive `EventId?` field on `TodoItem` (the `ProjectId`
   shape — an association + feed-filter, **never a gate**, C-M14·1); one
   reverse read seam `ListTodosForEventAsync` (the `ListTodosAsync`
   candidate-filter + `CanSeeAsync(Read)` + `HasMore` + aggregate
   `AccessAudit` shape, filtered `EventId == eventId`); one write lane
   `SetTodoEventAsync` (creator ∪ assignee ∪ GlobalAdmin, the `set-project`
   shape); and **both-direction display links** (to-do → event chip via the
   frozen `IEventService.GetAsync`; event → linked to-dos via the new seam),
   each **access-scoped + dangling-safe** (the `ProjectLink`/`BlockerChip`
   idiom, C-M14·2). The composition is **Web-layer** (D2) — no new
   cross-context Core dependency.
2. **The calendar interlock (D4, [PROPOSED — veto-able]).** The to-dos'
   existing optional `DueAt`/`StartAt` become a **`VTODO` iCal surface**: a
   **BCL-only pure `TodoIcsWriter`** (the `IcsWriter` discipline) + two
   `[Authorize]` routes (`GET /projects/todos.ics` the visible dated to-dos,
   always 200; `GET /projects/todos/{id}.ics` one `VTODO`, the
   404-not-403 split) + two quiet `kw-l` affordances.

Author the primary tier and the decision record, locking the register's
[PROPOSED] set (D1–D8) — or recording any **veto** the user made, with the
locked text replacing it:

- **D1 · A field, not a link doc.** `public string? EventId { get; set; }`
  on `TodoItem` (the `ProjectId` shape). **1:1.** Optional `(EventId)` feed
  index in `M5DocTypes` (the `(ProjectId)` precedent). **[Veto: a many-to-
  many `EventTodoLink` doc — then `ListTodosForEventAsync` reads the link
  table.]**
- **D2 · Both display directions are Web-layer composition over the two
  frozen read seams.** to-do → event via frozen `IEventService.GetAsync`;
  event → to-dos via new `IProjectService.ListTodosForEventAsync` (the
  `ListBoardsForTodoAsync` "list X for a Y" precedent). **No**
  `Kumunita.Core.Events` → `Kumunita.Core.Projects` dependency.
- **D3 · A dedicated `set-event` write lane (the `set-project` shape), not
  a create/edit form field.** `SetTodoEventAsync(string todoId, string
  actorId, IReadOnlySet<string> actorRoles, string? eventId,
  CancellationToken ct)` — creator ∪ assignee ∪ GlobalAdmin; to-do
  `!IsDeleted`; a non-visible `eventId` refused (404); `null` clears; one
  `AccessAudit` row `todo.set_event` (C3). Web: `POST
  /projects/todos/{id}/set-event`. **Not** on `CreateTodoRequest` /
  `UpdateTodoRequest`.
- **D4 · [VETO-ABLE] The `VTODO` surface is in M14.** `TodoIcsWriter`
  (new static class in `Kumunita.Core/Events/`) — BCL-only pure,
  `BuildTodos(IReadOnlyList<TodoItem>, DateTimeOffset nowUtc)`; one `VTODO`
  per **dated** to-do (`DueAt != null || StartAt != null`); closed subset
  `UID` (`kw-todo-{Id}@kumunita`) / `DTSTAMP` / `DUE` (if set) /
  `DTSTART` (if set) / `SUMMARY` / `DESCRIPTION` (if non-empty) /
  `STATUS` (if `IsDeleted`); CRLF / 75-octet fold / escape / stable `UID`;
  a valid empty calendar. **Never emitted** (C-M14·5 / ADR 0028):
  `ORGANIZER` / `CREATED-BY` / `ATTENDEE` / `RRULE` / audience / internals /
  any `X-…`. Web: two `[Authorize]` routes + the `text/calendar` serve
  idiom (ADR 0034/0108) + the two `kw-l` affordances. **[Veto: defer
  `VTODO` to its own lane — then M14 = the data interlock only, U05/U06
  skipped, U07 keeps its number.]**
- **D5 · No new authorization surface** (C-M14·4 / C-M5·11). Reuse the
  existing `TodoItemToAuditableResource` / `EventToAuditableResource`
  adapters + the frozen `IAuthorizationService` path; `set-event` standing
  reuses C-M5·6.
- **D6 · `RRULE` / recurring is **M18's home, NOT M14's.** `Milestones.cs`
  is the source of truth (M18 = "Recurring events"); ADR 0112 + the
  `IcsWriter.cs` doc-comment "M14's home" refs are **stale forward-refs**.
  M14 emits **no** `RRULE`, adds **no** recurrence field to `Event`
  (C-M14·6). **You record this clarification in the design doc + ADR 0115
  Consequences.**
- **D7 · Invariants + FACES + the pinned test list** — copy + refine the
