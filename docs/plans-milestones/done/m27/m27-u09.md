# M27 U09 — Core acceptance tests: the round-trip + no-secret/self-scoped + per-entity conflict

## Context (self-contained)

M27 = **user-scoped portability**: a resident exports/imports **their own
authored data** and resolves per-entity conflicts. U03–U06 shipped the
resident-scoped `UserPortabilityService` (export + classify + resolve model +
apply). U09 implements the **three acceptance tests** (the closed-loop /
handoff / part-vs-whole shape) from the design doc §gate (D8) in
`tests/Kumunita.Core.Tests/UserPortabilityAcceptanceTests.cs` (the M11
`PortabilityService` round-trip test is the shape to mirror — the
`PostgresFixture` harness + the media temp-dir + the seed-and-assert pattern).
**This unit does NOT author the Web pins** (U10) **and does NOT record the
gate** (U11) — each is a distinct unit for atomic handoff.

## Goal

Implement the **three acceptance tests** (the exact pinned names from the
design doc §2.6) in
`tests/Kumunita.Core.Tests/UserPortabilityAcceptanceTests.cs`:

1. **(a) round-trip** — plant a resident's authored footprint (a `Post` +
   reply + translation in a group the resident is a member of, an `Event` they
   authored, a `TodoItem`, a `Conversation` + `Message`, a `Document`, a `Page`
   they authored, their `Profile` bio/tags, their media) → **export** at the
   resident scope → import into a **fresh** instance where those groups/pages
   *do* exist → the clean entities are restored referentially intact (the
   "handoff" — the resident's data moves).
2. **(b) no-secret + self-scoped** — the exported archive contains **no**
   credential material and **only** the resident's authored/owned rows (another
   resident's `Post`/`Message` is **absent** — the D1 scope pin) (the
   "closed-loop" on the trust boundary + scope).
3. **(c) per-entity conflict resolution** — import into a target where the
   resident's group/page *do not* exist → the `conflict` entities are **not**
   auto-applied, the resident resolves each (add-elsewhere re-points to a
   member-of target and applies; discard drops it) and a discarded entity
   writes **nothing** (the "part-vs-whole" — the whole import is the
   resident's choice per entity, not a silent auto-merge).
