- `## 3. The design decisions` — each **[PROPOSED]** until U01 locks them:
  - `### 3.1 One bounded context, four documents, one surface, additive (D1)`
    — `Kumunita.Core.Projects` with `TodoItem`, `KanbanBoard`, `KanbanLane`,
    `BoardItemPlacement`; one new surface `M5DocTypes` (the `M4DocTypes`
    pattern verbatim); Marten-native POCOs, conventional `string` `Id`,
    delta-detected + idempotent, no seeding, no EF, zero migrations for
    existing surfaces (ADR 0004 §B.1).
  - `### 3.2 The canonical names (D2)` — the §5 sketch
    (`Project` / `ProjectTask` / `ProjectMember`) is settled as
    **`TodoItem`** (the to-do / work item), **`KanbanBoard`** (the board),
    **`KanbanLane`** (a board's column), **`BoardItemPlacement`** (a to-do's
    presence on a board/lane); `Project` / `ProjectTask` / `ProjectMember` do
    not exist (a "project" is not a distinct doc in M5 — a to-do is the unit;
    a board is the container). The §5 sketch is the pre-decision shape; U13
    rewrites the ARCHITECTURE.md §5 block + the §3 tree.
  - `### 3.3 A to-do is standalone; placement is a separate record (D3)` —
    `TodoItem` carries **no** `BoardId` / `LaneId` / `Order`; its presence on
    a board (and its position) is a `BoardItemPlacement` row. A to-do has
    zero or many placements (on several boards). Move up/down = reorder
    within a lane; move left/right = change lane (same board); move-to =
    relocate the placement; copy-to = duplicate the to-do + place the copy.
  - `### 3.4 Read is the to-do's own `Audience`; the board is a container (D4)`
    — `TodoItem` and `KanbanBoard` each carry the **exact** post `Audience`
    (ADR 0001-B / 0036; `null` = public) and each has its own adapter
    (`TargetKind "todo"` / `"board"`). A standalone to-do list / detail is
    gated by the to-do's `Audience` (C-M3·3 aggregate / C3 404-vs-403). A
    board view is gated by the board's `Audience` (entry), then each card by
    the to-do's own `Audience` (visible iff **both**); a `BoardItemPlacement`
    is not itself an auditable resource (it inherits its to-do's decision).
  - `### 3.5 Status is a string, not an enum (D5)` — `TodoItem.Status` and
    `KanbanLane.Status` are **nullable strings** (the state label; `null` =
    none). **No** status enum, no registry, no seeded vocabulary. The lane
    vocabulary is whatever the board's lanes name. Moving a to-do into a lane
    whose `Status` is non-null sets `TodoItem.Status` to that lane's status
    (auto-update, audited, in the same transaction — C3); a lane with null
    `Status` leaves the to-do's status unchanged. The **status icon is a
    client-side display** mapping (C-M5·9), never persisted.
  - `### 3.6 Lane limits are advisory backstops, refused not dropped (D6)` —
    `KanbanLane.MaxItems?` (`null` = no limit) caps the placements a lane
    holds; a move/copy **into** a lane at its limit is **refused** (a
    message; nothing written). Reorder within a lane and move *out* never
    trip the source limit. The limit counts placements in that lane.
  - `### 3.7 Hierarchy is `ParentId` only; a subtask is a full to-do (D7)` —
    `TodoItem.ParentId?` is the sole hierarchy mechanism; a subtask has its
    own status / assignee / placements. **Delete cascades** to the descendant
    subtree. A `ParentId` that would create a cycle is refused. Subtasks list
    under their parent and may also appear as their own cards.
  - `### 3.8 Standing is creator ∪ assignee ∪ GlobalAdmin, re-checked server-side (D8)`
    — the Web `[Authorize]` is a convenience pre-gate only; `IProjectService`
    enforces the matrix for every mutating lane (the ADR 0014 / 0016 / 0017
    precedent). The creator is `AuthorId`; the assignee is `AssigneeId`
    (assignment grants standing); GlobalAdmin is the override branch.
    `AssigneeId` is display + standing, **never an access gate** (read is the
    `Audience` decision — D4).
  - `### 3.8a No draft lane (D8a)` — the ADR 0037 `IsDraft` pin is **out of
    scope for M5**. A to-do is **published on creation** (the
    `CreateTodoAsync` write lane does not set a draft flag; `TodoItem` has
    no `IsDraft` field). The ADR 0037 author-only draft + `/my/drafts` lane
    is a **follow-on lane** (own ADR), not part of M5. `KanbanBoard` likewise
    has no `IsDraft` (a board is live on creation; the `/my/drafts` lane for
    boards is out of scope).
  - `### 3.9 Copy-to duplicates; move-to relocates (D9)` — "Copy to (board)"
    = a new `TodoItem` copy (title / status / assignee) + a placement on the
    target board's first lane; the original is untouched. "Move to (board)" =
    the placement is removed from the source board and added to the target
    board's first lane.
  - `### 3.10 Plain TS, zero deps, explicit server round trips (D10)` —
    tsc-only (ADR 0031); **no UI library, no bundler**;
    `client/lib/projects-board.ts` is the one new module. Every action
    (reorder / move / copy / assign / delete) is an **explicit POST**,
    CSRF-aware (the `client/lib/api.ts` shape), then a full re-render — **no**
    optimistic local reordering, **no** HTML5 drag events (keyboard / menu
    driven). The status icon + assignee avatar + dropdown are plain DOM / JS.
  - `### 3.11 Localization parity (D11)` — the new `kw-l` keys (to-do / board
    / lane nouns, the action labels, the lane limit / status labels, the
    board empty-state) are present in **all four** seeded languages
    (en/de/fr/da); English is the fallback in every view; the ADR 0015
    key-registry shape is the host.
  - `### 3.12 Reuse, don't reinvent (D12)` — the `Audience` doc, the frozen
    `IAuthorizationService`, the standing matrix, the `MarkdownRenderer` +
    `bindRichEditor`, the `kw-dt` TagHelper, the profile-avatar surface are
    all **frozen seams** — M5 adds **adapters + a service + views + one TS
    module**, not a branch. **No new `AccessAction`**, **no new
    `AccessVia`**, **no new authorization path**, **no editor dependency**.

  `Audience` / a to-do on the board is visible iff **both** are visible;

  a further move/copy into it (below the limit it accepts); F7 the assignee

  placement) shown under its parent / deleting a to-do cascades to its
