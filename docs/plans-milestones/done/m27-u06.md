# M27 U06 — Import: the `ResolveAsync` fail-closed apply (the resident's choice)

## Context (self-contained)

M27 = **user-scoped portability**: a resident imports **their own authored
data** and resolves per-entity conflicts. U04 shipped the `ClassifyAsync`
classification. U05 pinned the resolve model (the
`UserPortabilityEntityResolution` POCO set: `AddElsewhere` re-point or
`Discard`). U06 renders **D4's apply half** as code:
`UserPortabilityService.ResolveAsync` — apply **only** the entities the
resident resolved, in the M11 dependency order, re-pointing each `AddElsewhere`
entity's absent reference to the **target the resident picked** (reusing the
resident's **own existing write lane** for each doc family — the post/event/
project/document/page create seams, **not** a new bulk importer), and writing
**nothing** for a `Discard`ed entity. **Fail-closed:** a mid-apply failure is
the documented rollback path, never a silently-accepted half-apply (C-M27·4).
One `AccessAudit` row (`Via = Owner`, `TargetKind "portability"`, verb
`import.resolve`). **No auto-merge:** a `conflict` entity the resident did
**not** resolve is **not** applied (C-M27·4/5).

## Goal

Fill in the `UserPortabilityService.ResolveAsync` body (the per-resolved-
entity apply, the re-point rule, the fail-closed contract, the no-auto-merge
pin, the one `AccessAudit` row `Via = Owner` verb `import.resolve`) + author
the **apply pins** in
`tests/Kumunita.Core.Tests/UserPortabilityResolveTests.cs` (the
`AddElsewhere` re-point applies to the picked target; the `Discard` writes
nothing; the no-auto-merge pin — an unresolved `conflict` entity is absent
after apply; the fail-closed pin — a mid-apply failure leaves zero new rows).
