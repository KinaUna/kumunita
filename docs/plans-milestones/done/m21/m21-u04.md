### 2. `src/Kumunita.Web/Views/Documents/Index.cshtml` (new)

The feed (mirror `Announcement/Index.cshtml`). The model is U03's
`DocumentIndexViewModel` (`Visible`, `HasMore`, `Page`, `CanUpload`):

- `@model Kumunita.Web.Models.DocumentIndexViewModel` + `@using
  Kumunita.Core.Documents`.
- `<h1><kw-l key="documents.title">Documents</kw-l></h1>`.
- The upload button gated on `@Model.CanUpload` (the D5 standing resolved at the
  Web boundary by U03) → `href="/documents/new"` with
  `<kw-l key="documents.upload">…</kw-l>`.
- Empty state → `<kw-l key="documents.empty">…</kw-l>` when
  `@Model.Visible.Count == 0`.
- The feed rows: each `d in Model.Visible` → a link to `/documents/@d.Id` (the
  detail) + a download link to `/documents/@d.Id/download` with
  `<kw-l key="documents.download">…</kw-l>`.
- Paging: a "next" link iff `@Model.HasMore` → `/documents?page=@(Model.Page + 1)`.

> **Razor doctrine (from AGENTS.md):** a URL that shows a **literal
> `@Model.X`** is the uninterpolated-attribute bug — in the href, write
> `href="/documents/@d.Id"` (the `@` interpolates the model member), not
> `href="@d.Id"`. The download href follows the same shape.
