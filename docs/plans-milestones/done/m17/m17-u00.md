**The [PROPOSED] lock set (from the register — lock these **verbatim**):**

- **D1 — One document, one new surface, one new bounded context.** A new
  bounded context `Kumunita.Core.Bookmarks` with **one document**:
  `Bookmark` (`OwnerId`, `TargetKind`, `TargetId`, `Created`), on a **new
  `M17DocTypes`** surface (M9/M5 precedent, additive, idempotent, zero
  migrations). `TargetKind` is a **string** restricted to the closed set
  {`post`, `event`, `todo`, `announcement`, `page`} — the exact vocabulary the
  existing `*ToAuditableResource` adapters already emit (the M5
  `KanbanStatuses` string-not-enum shape). *Forbids:* a document per surface;
  an enum type for `TargetKind`; a migration of an existing surface.
- **D2 — A bookmark is a personal-by-id record, never an audience decision.**
  No adapter, no new `AccessAction`/`AccessVia`/`Decide()` branch, no new
  method on `IAuthorizationService` (the M9 ADR 0105 shape). The owner's own
  list is a personal read (like the M6 inbox): no `CanSeeAsync` pass over the
  bookmark rows. *Forbids:* a `BookmarkToAuditableResource`; running the
  owner's own list through `IAuthorizationService`.
- **D3 — Bookmarking requires visibility; bookmarking grants nothing.** The
  write lane re-runs the target's frozen `Read` decision (`CanAsync(Read)`
  over the target's existing adapter — the *same call the detail page uses*)
  and refuses **404** (not 403; no Deny row survives) when the target is not
  visible. The bookmark row never appears in, widens, or is consulted by any
  `CanSeeAsync` pass anywhere. *Forbids:* bookmarking an invisible target; a
  bookmark consulted by any read decision; a `GlobalAdmin` peek branch.
- **D4 — One row per (owner, target); toggle = idempotent add / remove.** The
  unique index on `(OwnerId, TargetKind, TargetId)` is the witness; a second
  bookmark is a **no-op**; unbookmark removes the row. **No** `IsDeleted`
  flag — removal is physical (a bookmark is a *pointer*, not content); a
  re-bookmark is a fresh `Created`. *Forbids:* an `IsDeleted` on `Bookmark`;
  a second row for the same (owner, target); mutating `Created`.
- **D5 — The list degrades, never leaks.** A row whose target is absent,
  soft-deleted, or no longer visible renders the generic `bm.list.degraded`
  label — **no title, no link, no id** — and the unbookmark control still
  works on the degraded row. *Forbids:* a 404/403 on a dangling row; leaking a
  removed target's title.
- **D6 — M17 is a core surface, not a lane: no off-by-default toggle.** No
  admin toggle, no `LocaleSettings`-style switch. *Forbids:* an off-by-default
  toggle.
- **D7 — No notification lane in M17 (deferred).** Composes only the frozen
  `IAuthorizationService` (D3) + the owning surfaces' existing read seams
  (D5) over `IDocumentStore`. No `INotificationService`, no Wolverine
  handler. *Forbids:* an `INotificationService` in the composition; a Wolverine
  handler.
- **D8 — The close flip is one atomic unit (U05).** `Milestones.cs`
  M17→done/M18→next; `MilestonesTests.cs` re-pinned to
  `M18_Is_The_Single_InProgress_Milestone` + shipped list gains M17 + M19
  planned; README Roadmap/Status; `docs/STATUS.md`; `docs/ARCHITECTURE.md`
  value-chain M17 row. All four in the same unit. *Forbids:* reordering
  M18/M19; breaking the pins; flipping one surface and not the others.

- **C-M17·1 — The bookmark is a personal-by-id record; the surface adds zero
  authorization** (no adapter, no new action/via/branch, no new
  `IAuthorizationService` method; the only authorization call in the
  milestone is the D3 write-lane check, which is the *target's own* frozen
  `CanAsync(Read)`).
- **C-M17·2 — The owner's list is a personal read, audited zero** (no
  `CanSeeAsync` pass over the bookmark rows, no `AccessAudit` row for the
  owner's own list; a non-owner — a `GlobalAdmin` included — gets a non-leaky
  **404** that commits **no** `AccessAudit` row either — the ADR 0105
  "operator has no read standing" precedent).
- **C-M17·3 — Bookmarking requires visibility; bookmarking grants nothing**
  (the write lane re-runs the target's frozen `Read` decision before creating
  the row; Deny ⇒ 404, no Deny row survives; the row never widens any
  audience).
- **C-M17·4 — One row per (owner, target); toggle is idempotent** (the unique
  index makes a duplicate a no-op; unbookmark removes; `Created` never
  mutated; no `IsDeleted` — a bookmark is a pointer, not content).
- **C-M17·5 — The list degrades, never leaks** (dangling row ⇒ the closed
  `bm.list.degraded` label, no title/link/id; unbookmark still works).
- **C-M17·6 — M17 is a standing core surface (no toggle).**
- **C-M17·7 — The close flip is atomic** (D8).

- **FACES F1–F5 + the named trade** (the register's wording): F1 the toggle
  is idempotent and atomic (the unique index is the witness — the M9
  `convo_uidx_pair` shape); F2 the write lane is the target's own frozen
  decision (invisible target ⇒ 404, no row); F3 the list is the owner's
  personal read (zero audit, zero `CanSeeAsync` over the rows); F4 a dangling
  bookmark degrades, never leaks (the `bm.list.degraded` closed key; unbookmark
  still works); F5 a standalone core surface (D6). **Named trade:** the
  dangling-row UX vs. the leak surface — the row survives its target's death
  (a silently-removed bookmark is worse than a greyed-out one), and the leak
  surface of a dangling row is exactly **one static `kw-l` string** with no
  title, link, or id.

- **§kw-l key list** (the `bm.*` keys × en/de/fr/da — U03's source of truth):
  `bm.nav`, `bm.list.title`, `bm.list.empty`, `bm.list.degraded`,
  `bm.list.kind.post`, `bm.list.kind.event`, `bm.list.kind.todo`,
  `bm.list.kind.announcement`, `bm.list.kind.page`, `bm.list.unbookmark`,
  `bm.button.bookmark`, `bm.button.bookmarked`. (Adjust names to the views as
  you author them; the **list** is what U03 registers — the count/names are
  locked here so U03 and the parity tests agree.)

- **§gate — the three acceptance tests** (U05 adds them):
  (a) **closed-loop** (a resident bookmarks a post they can see → it appears
  in their `/bookmarks` under the `post` group → they unbookmark it → it is
  gone; a second bookmark of the same post is a no-op — one row, one
  `Created`);
  (b) **handoff-authorization-boundary** (bookmarking a post the resident
  *cannot* see ⇒ 404, no row, no Deny row surviving; a `GlobalAdmin` who is
  not the owner of a bookmark list gets a 404 with **no** `AccessAudit` row —
  the C-M17·2 zero-audit personal read);
  (c) **part-vs-whole-audit-completeness** (the owner's own list load commits
  **zero** `AccessAudit` rows — C-M17·2 — while the *write* lane's single
  `CanAsync(Read)` check is the target's own frozen decision (C-M17·3): the
  part (one toggle) and the whole (the list) audit differently by design, and
  both pins hold together).

- **§deferred:** the "nudge the author on bookmark" lane (D7); bookmark
  folders / manual ordering; bookmark sharing / per-surface "top bookmarked"
  stats — each "own ADR".

- **§drift-guard — the frozen pins + the drift log:** the frozen seams
  (`IAuthorizationService`, `AccessAction`, `AccessVia`, `Decide()`), the
  D1–D8 decisions, the C-M17·* invariants, the §kw-l list, the §gate names,
  the closed `TargetKind` set. A change to any of these after U00 is a
  **drift event** (record it in the drift log).
