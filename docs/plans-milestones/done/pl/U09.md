# U09 — Delete lanes (soft) for goals + projects

**Goal:** add the **soft-delete** surface for goals + projects: the
**two delete seams** on `IProjectService` (**`DeleteGoalAsync`** /
**`DeleteProjectAsync`** — the ADR 0024 `IsDeleted` shape, the standing
re-check, the **D6 dangling-association rule** — deleting a goal does
**not** touch its projects' `GoalId`, deleting a project does **not**
touch its to-dos' / boards' `ProjectId` — the associations become
*dangling* and their links are not rendered, per U06/U07/U08's
existing `GetGoalAsync` / `GetProjectAsync` 404-on-soft-deleted
behavior) + the **two POST routes** (`POST /projects/goals/{id}/delete`,
`POST /projects/projects/{id}/delete`) + the **delete buttons** on
`GoalDetail.cshtml` / `ProjectDetail.cshtml` (the ADR 0058
`confirm()` guard). **`dotnet build` + `npm run build` clean; Web tests
pass; all M5 + U02–U08 pins still pass** (the additive-surface pin).

- `src/Kumunita.Core/Projects/IProjectService.cs` (edit): the two
  delete seams, in the new `// --- PL delete lanes (U09) ---` section —

- `src/Kumunita.Core/Projects/ProjectService.cs` (edit): the two
  implementations — `DeleteGoalAsync`: load the goal (404 if absent /
  soft-deleted), the **standing re-check** (creator ∪ GlobalAdmin —
  the ADR 0070 shape, 403 if denied), set `IsDeleted = true`, stamp
  `Modified`, the `goal.delete` `AccessAudit` row
  (`TargetKind = "goal"`) — **no** cascade to `Project.GoalId` (the
  D6 rule — the projects keep their `GoalId` value, their goal link
  is not rendered, per U07's existing `GetGoalAsync` 404-on-soft-deleted
  behavior); `DeleteProjectAsync`: the same shape over the project —
  load (404), standing re-check (403), `IsDeleted = true`,
  `Modified`, the `project.delete` `AccessAudit` row
  (`TargetKind = "project"`) — **no** cascade to `TodoItem.ProjectId`
  / `KanbanBoard.ProjectId` (the D6 rule).
- `src/Kumunita.Web/Controllers/ProjectsController.cs` (edit): the two
  POST actions, **mirroring the existing M5 delete-route convention
  exactly** (confirmed: `POST /projects/todos/{id}/delete` →
  `DeletePost` action, `TempData["info"]` + redirect; `POST
  /projects/boards/{id}/delete` → `BoardDeletePost` action, the same
  shape): `POST /projects/goals/{id}/delete` → `GoalDelete(string id)`
  → `DeleteGoalAsync`, `TempData["info"]` + redirect to the `/projects`
