# U05 — `/projects` landing page (goals + standalone projects) + the "Projects" nav tab

**Goal:** add the **Web landing surface** for the lane: `GET /projects`
renders a two-section feed — **goals** (cards: title, description,
"New project under this goal" affordance) + **standalone projects**
(`GoalId == null` cards: title, description, status, start/due dates, goal
link) — and the **"Projects" tab** becomes the first entry of the
`_ProjectsTabs` trio (Projects / To-dos / Boards), active-tab derivation
extended so `ProjectsIndex` activates it. **`dotnet build` + `npm run
build` clean; Web tests pass; the M5 `/projects/todos` + `/projects/boards`
routes render exactly as before** (the frozen M5-route pin).

**Entry reads:** U04's handoff section (the association lanes exist +
`dotnet build` clean); `docs/design/pl-goals-projects-design.md` §5 (the
landing-page wire — the two sections, the card shapes, the nav-tab order,
the `pl.*` key list); `docs/design/pl-goals-projects-design.md` §9.1
(the `pl.*` `kw-l` keys the landing uses); `src/Kumunita.Web/Controllers/ProjectsController.cs` (the
`[Authorize]` + `KumunitaPrincipal` actor-minting + `SeedComponentPickerAsync`
shapes to mirror; the existing M5 actions the new action sits alongside —
**do not reorder or rename any existing action**); `src/Kumunita.Web/Models/ProjectViewModels.cs`
(added by U01 if absent, extended here — the view-model record style);

shape + the active-tab derivation comment);
