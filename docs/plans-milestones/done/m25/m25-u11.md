## Understanding

This unit writes the **decision record** (ADR 0134) and the **docs sync**
(OPS.md's `Media__MaxBytes` row + the README Roadmap M25 entry) that distill
the shipped M25 behavior into the repo's durable docs. It is **not** the

repo's "keep the docs in sync with the code" contract (AGENTS.md) — a new
capability that settles a design question gets an ADR, and the config
reference (OPS.md) + the Roadmap (README) follow.

## Deliverables (≤ 3 files)

1. **`docs/adr/0134-upload-limits.md`** — the full ADR (Context / Decision /
   Consequences, mirroring ADR 0011's style).
   - **Context:** the platform's per-file size gate was env-only
     (`Media__MaxBytes`, 5 MiB) and duplicated per upload lane; there was no
     per-user total-content quota and no resident self-usage view (the M25
     promise).
   - **Decision:** (1) the admin-set **per-file size limit** + **per-user total
     content quota** live in a single community doc
     (`CommunityStorageSettings`, GlobalAdmin-set, the `Kumunita.Core.Usage`
     context), with the env `Media__MaxBytes` as the **fallback** (C-UP·5);
     (2) the size + quota check is a **pure Core** decision
     (`StorageLimits.Decide`) mapped by a thin **Web** gate (`IUploadGate`)
     adopted by **all four upload lanes** **before** `PutAsync`
     (guards-before-write, C-UP·2 — no byte written on a reject); (3) the
     per-user usage is **content-addressed** —
     `Σ MediaObject.SizeBytes WHERE CreatedById == subjectId` (C-UP·4, dedup
     inherent); (4) the resident sees **their own** usage / quota / remaining
     (a self-only read, C-UP·4/F7); (5) the sentinel semantics (quota `0` =
     unlimited; per-file limit unset = env fallback, C-UP·5); (6) the
     **named non-decisions** — per-resident individual quota overrides (future
     lane), the admin *metrics* tables (M24), serve-time enforcement, any
     `IMediaStore`/`MediaObject` reshape (C-UP·1/4). **Amends: 0011** (the
     `MaxBytes` boundary becomes the *fallback* for the admin-set per-file
     limit) **and 0034** (the per-lane gate is generalized to a shared
     admin-set limit + quota). **No new `AccessAction`/`AccessVia`/
     `AccessAudit`** (C-UP·7); **no new bounded context** (ADR 0006-D — the
     `Kumunita.Core.Usage` context).
   - **Consequences:** the `Media__MaxBytes` env knob is now the fallback (OPS
     annotated); the four upload lanes share one enforcement path (a
     single Web gate over a pure Core decision — `Core` stays HTTP-free,
     C-UP·3); a resident can see their own quota (a new resident-facing
     surface); the single-in-progress milestone contract is preserved (C-UP·6,
     the close is U12). The two restore surfaces (ADR 0011 C-MED·7) are
     unchanged.
2. **`docs/OPS.md`** — annotate the `Media__MaxBytes` row: it is now the
   **fallback** for the admin-set per-file limit (the in-app `/admin/storage`
   surface is the primary); the per-user quota is **admin-set in-app** (not an
   env knob). Keep the existing default (`5242880` = 5 MiB; `0` = no cap) and
   the "enforced at the upload boundary" note.
3. **`README.md`** — update the M25 Roadmap entry **text** if the
   scope/naming needs it (the **status** stays as-is — the flip is U12's).
