## Understanding

This unit closes the **test** surface of M25: it adds the **acceptance gate**
(design doc §2.5) as three named end-to-end tests (closed-loop / handoff /
part-vs-whole), adds the **FACES**-anchored tests not yet covered by U4/U9 (F1
success, F4 admin-raises-limit strong consistency, F5 quota-`0`-unlimited, F6
env-fallback, F9 no-byte-written-on-reject), and **records the M25
acceptance** in the handoff note (the total Core + Web test count). It is the
"part-vs-whole" unit — the seam tests (U4/U9) are the *parts*; the acceptance
tests are the *whole*; all must pass together.

## Deliverables (≤ 3 files)

1. **`tests/Kumunita.Core.Tests/Usage/StorageLimitsAcceptanceTests.cs`** — the
   three acceptance tests (mirroring the §2.5 gate):
   - **closed loop:** an admin sets a per-user quota + a per-file limit via
     `SetAsync`; a resident uploads a file within both → the upload **succeeds**
     (the `Decide` is `Allowed`) and the resident's own usage (via
     `GetPerUserUsageBytesAsync`) now reflects the new file's `SizeBytes`.
   - **handoff:** the *next* upload (the same or a second resident) that would
     push `currentUsage + incoming` over the quota is rejected
     (`Decide` → `OverQuota`, the Web gate → 413 over-quota) — **strong
     consistency, live doc** (the admin's `SetAsync` change re-scopes the *next*
     decision; F4/F3).
   - **part-vs-whole:** the 23-test list (Core §2.3 + Web §2.4) is the whole;
     closed-loop + handoff are the parts; **all must pass together** (this test
     asserts the closed-loop and handoff outcomes jointly, or is a
     documentation-anchor test that fails if either is removed).
2. **`tests/Kumunita.Core.Tests/Usage/StorageLimitsTests.cs`** — add the
   FACES-anchored Core tests not yet covered: F5 `Decide_QuotaZero_Unlimited`
   (if not already item 4), F6 `EffectiveMaxFileBytes_UnsetFallsBackToEnv`
   (if not already item 6), F1 `Decide_WithinBoth_Allows` (if not already item
   3). Add only what is missing — do not duplicate U4's names.
3. **One representative per-lane test file** (e.g.
   `tests/Kumunita.Web.Tests/ProfileAvatarUploadTests.cs`) — add the F9
   **no-byte-written** assertion: an over-quota (or oversize) reject writes
   **no** volume file — assert `IMediaStore.PutAsync` was **not** called / no
   new `MediaObject` row. **One representative lane is sufficient** to pin
   C-UP·2/F9 (note *which* lane in the handoff note).
