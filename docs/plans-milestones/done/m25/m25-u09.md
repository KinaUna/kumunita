## Understanding

This unit pins the **enforcement** behavior at the Web level — each of the
**four** upload lanes rejects an **oversize** upload with 413 and an
**over-quota** upload with 413, with a **distinct** message for each reason
(F2/F3), and `Allowed` uploads still succeed. It extends the **existing**
per-lane test harness (the byte-backed `TestFormFile` `IFormFile` carrier the
codebase already uses in `AttachmentUploadTests.cs` / `ContentImageUploadTests.cs`
/ `DocumentControllerTests.cs` / `ProfileAvatarUploadTests.cs`), adding the
over-quota case (the existing tests cover oversize) + the distinct-message test.

## Over-quota fixture shape (the pin to keep consistent across the 4 lanes)

- Pre-seed the store with a `MediaObject` row whose `CreatedById` is the test
  subject (so `GetPerUserUsageBytesAsync(subject)` returns a positive
  `currentUsage`).
- Seed the `CommunityStorageSettings` doc with a **small** `PerUserQuotaBytes`
  (so `currentUsage + incoming > quota`) and a large `MaxFileBytes` (so the
  file is **not** oversize — the reject is over-quota, not oversize).
- For the oversize case: a `CommunityStorageSettings` with a **small**
  `MaxFileBytes` + a large `PerUserQuotaBytes` (so the reject is oversize, not
  over-quota).
- Assert the `413` status + that `IMediaStore.PutAsync` was **not** called
  (no byte written — C-UP·2; the full no-byte-written assertion is F9 in U10,
  but a quick `PutAsync` not-called check here is fine and keeps the lane
  honest).
