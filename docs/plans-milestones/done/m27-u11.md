# M27 U11 — run + record the M27 acceptance gate

## Context (self-contained)

M27 = **user-scoped portability**: a resident exports/imports **their own
authored data** and resolves per-entity conflicts. U09 implemented the three
Core acceptance tests. U10 implemented the Web-surface pins. U11 executes and
**records** the three-test acceptance gate (U09's Core round-trip / no-secret /
per-entity + U10's Web pins) from the design doc §gate, *using* U09/U10's
tests as the part-vs-whole evidence. The **gate section** is appended to the
design doc (the M2 U10 / M11 U07 analog — the "run the record" step, split
from U09/U10 so the test-authoring units stay atomic). **If a Core test's
runtime (Postgres-boot + a media temp-dir) is not yet present, the spec is
authored (mirroring the M3/M4 author-not-run precedent) and *not* run — the
gap is recorded in the design doc + the handoff note + the next unit who
lands the runtime records the pass count.**

## Goal

Run the M27 test suites (per AGENTS.md: `dotnet build Kumunita.slnx -c Debug`,
then `dotnet exec tests\Kumunita.Web.Tests\bin\Debug\net10.0\Kumunita.Web.Tests.dll`
+ `dotnet exec tests\Kumunita.Core.Tests\bin\Debug\net10.0\Kumunita.Core.Tests.dll`)
and **record** the gate: append `### Run result (M27 acceptance gate —
<date>)` to the design doc — the three Core test names + their pass/red
status, the Web-pin count, one line per any `## U<m> — Drift pause` section in
the handoff note (each resolved or still open). **No code, no build beyond the
test run.**
