# M26 U16 — i18n: the `sort.*` kw-l set × en/de/fr/da + a resolution pin

> **Sealed unit.** One fresh agent, ~32K context window. Self-contained. The
> register (`docs/plans-milestones/plan-m26-sorting.md`) is the
> cross-reference; when the two disagree, **this file wins for what to do**.
> **Exit: build green + the `SortKwL_Resolves_En_De_Fr_Da` test passes.**
> **Precondition:** U15's `_Sort` partial uses `<kw-l key="sort.…">` labels.

## Understanding

This unit closes the **`sort.*` kw-l set** (the sort control's option labels
— the per-key names, the asc/desc labels, the control's accessible label)
across **en/de/fr/da** with an English floor (the M25 `documents.*` / `a11y.*`
precedent), wires it into the `_Sort` partial (F12), and pins a **resolution
test** that the labels resolve in all four languages. **Label-only** — no
logic change to the `_Sort` control. The English floor is **always present**
(a missing de/fr/da key degrades to en, the ML-UI floor rule).

## Entry reads (3–5 files)
- U2's §2.4 (the `_Sort` contract's `<kw-l key="sort.…">` usage) — the key
  names to close.
- `src/Kumunita.Web/Views/Shared/_Sort.cshtml` (U10's partial) — the exact
  `<kw-l>` keys it references (align the closed set to these names).
- `src/Kumunita.Core/Localization/KnownTranslationKeys.cs` — the **closed-
  set registry** (the `["documents.*"]` / `["a11y.*"]` precedent to mirror);
  the English-floor source text lives here.
- `src/Kumunita.Core/Localization/ITranslationProvider.cs` (the resolution
  seam the test drives) + `LocalizationService.cs` (the fallback chain:
  preferred → default → en → registry floor).
- The M25 kw-l precedent — `docs/plans-milestones/done/m25/` + the `documents.*`
  registration in `KnownTranslationKeys.cs` (how a closed set is added + how
  the English floor is pinned) + `tests/Kumunita.Core.Tests/MLUI_FacesTests.cs`
  or `tests/Kumunita.Web.Tests/MLUI_FacesTests.cs` (the resolution-pin test
  shape to emulate).

## Deliverables (≤ 3 files)
1. **`src/Kumunita.Core/Localization/KnownTranslationKeys.cs`** — add the
   `sort.*` keys (the key names matching the `<kw-l>` usage in the `_Sort`
   partial — e.g. `sort.label`, `sort.asc`, `sort.desc`, `sort.created`,
   `sort.modified`, `sort.title`, `sort.name`, `sort.start`, `sort.due`,
   `sort.priority`, `sort.status`, `sort.size`) with the **en floor** text;
   add the **de/fr/da** rows (one `TranslationResource` per (key, language))
   via the same seeder/registration path the `documents.*` set uses.
2. **`src/Kumunita.Web/Views/Shared/_Sort.cshtml`** (if the key names need
   aligning to the closed set) — a **label-only** edit (the `<kw-l>` key
   names); **no logic change**.
3. **A pinned test** (`tests/Kumunita.Core.Tests/` or `Web.Tests/` —
   `SortKwL_Resolves_En_De_Fr_Da`, the F12 pin) — asserts every `sort.*` key
   resolves in en (the floor), de, fr, and da (no blank, no missing-key
   degradation on the closed set).

## Rules
- **Label-only** — no logic change to the `_Sort` control (C-SORT·3 is
  unaffected).
- The **English floor is always present** (a missing de/fr/da key degrades to
  en, the ML-UI floor rule).
- **Do not** invent keys beyond the closed set (the `a11y.*`/`documents.*`
  closed-set precedent) — the key set must match what the `_Sort` partial
  actually references.
- **Do not** touch the seeder's existing `en` rows (the M·1 "a resident never
  sees a blank label" rule).
