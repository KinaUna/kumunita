## Deliverables (4 files + pins)

### 1. `LocaleController.cs` — the 5th section

**Inject** `NotificationService notifications` into the primary-constructor
(the U02/U04 seam owner; it is already DI-registered).

**Add the quiet-schedule fields to `LocaleSettingsViewModel`** (the shared
view model the 4 sections use): a `bool QuietEnabled`, a `string QuietMode`
("blocked"/"allowed"), `int[] QuietHours` (0–23), `int[] QuietDaysOfWeek`
(0–6, Sunday-first), and the existing `Quiet` read-through. (The view renders
only the quiet section, but the model carries the whole surface — the
`BuildModel()` single-model shape.)

**GET action** (mirror `SettingsTimezone`):

```csharp
/// <summary>
/// GET /settings/quiet — the resident's quiet-hours section (ADR 0121 D2) on
/// its own linkable page (ADR 0080). The model is the full
/// LocaleSettingsViewModel; the view renders only the quiet section. The
/// schedule is read through the U02 owner-scope seam for the signed-in
/// subject (owner-scope — the page always resolves the signed-in subject,
/// never a caller-supplied id).
/// </summary>
[HttpGet("/settings/quiet")]
public async Task<IActionResult> SettingsQuiet()
{
    return View("Quiet", await BuildModel());
}
```

**POST lane** (mirror `SaveTimezone` — owner-scope, no audit row, `clear=1`
clears):

```csharp
/// <summary>
/// POST /settings/quiet — the quiet-hours save (ADR 0121 D2). Owner-scope:
/// the recipient is ALWAYS the signed-in subject (SubjectId(User)) — there is
/// no caller-supplied recipient id, so a resident cannot write another
/// resident's schedule (the C-M20·7 owner-scope rule, the SaveTimezone shape
/// verbatim). With clear=1: the U02 seam with a null schedule (= never
/// quiet, the floor). Otherwise: build a NotificationQuietSchedule from the
/// form (enabled, mode, hours, days) and store it through the same seam.
/// No AccessAudit row (the owner-scope personal-preference lane, ADR 0019).
/// </summary>
[HttpPost("/settings/quiet")]
[ValidateAntiForgeryToken]
public async Task<IActionResult> SaveQuiet(
    bool enabled,
    string? mode,
    int[]? hours,
    int[]? daysOfWeek,
    string? clear)
{
    var subject = SubjectId(User);
    if (string.IsNullOrEmpty(subject))
        return RedirectToAction(nameof(SettingsQuiet));

    if (clear == "1")
    {
        await notifications.SetQuietScheduleAsync(subject, null);
        TempData["info"] = await FlashAsync("settings.quiet.flash_cleared");
    }
    else
    {
        var schedule = new NotificationQuietSchedule
        {
            RecipientId = subject,
            Enabled = enabled,
            Mode = mode == "allowed" ? QuietScheduleMode.Allowed : QuietScheduleMode.Blocked,
            Hours = hours ?? Array.Empty<int>(),
            DaysOfWeek = daysOfWeek ?? Array.Empty<int>(),
        };
        await notifications.SetQuietScheduleAsync(subject, schedule);
        TempData["info"] = await FlashAsync("settings.quiet.flash_saved");
    }

    return RedirectToAction(nameof(SettingsQuiet));
}
```

**Extend `BuildModel()`** to populate the five quiet fields from
`await notifications.GetQuietScheduleAsync(subject)` (a `null` schedule →
`QuietEnabled = false`, the "never quiet" floor).

### 3. `Views/Locale/Quiet.cshtml` — the section view

Render the quiet section from `LocaleSettingsViewModel`:

- A **master on/off** (`settings.quiet.enabled`) — `enabled` checkbox bound to
  `Model.QuietEnabled`.
- A **mode** radio (Blocked / Allowed) — `settings.quiet.mode_label` heading
  + `settings.quiet.mode_blocked` / `settings.quiet.mode_allowed` options,
  bound to `Model.QuietMode` (the `settings.quiet.mode_*` keys are the two
  radio labels).
- **Hours** multi-select (0–23) — `settings.quiet.hours_label` heading, bound
  to `Model.QuietHours`.
- **Days** multi-select (0–6) — `settings.quiet.days_label` heading, bound to
  `Model.QuietDaysOfWeek`.
- A **Save** button — `settings.quiet.save`.
- A **Clear** (reset to never-quiet) button posting `clear=1` — reuses
  `settings.quiet.flash_cleared` on success (the ADR 0019 "reset to platform
  default" affordance shape).
- The `settings.quiet.title` heading + `settings.quiet.description` lead line.

Every user-visible string is a `kw-l` key from Deliverable 4 — **no hardcoded
copy** (the ADR 0015 closed-key discipline). The form posts to

### 5. Web pin tests (≥3, in `tests/Kumunita.Web.Tests/`)

- **Pin 1 — save/clear round-trip (owner-scope).** POST
  `/settings/quiet` with `enabled=true`, `mode=blocked`, `hours=22,23` → the
  `NotificationService.SetQuietScheduleAsync` seam is called for the
  **signed-in subject** with that schedule (assert via a faked
  `NotificationService`). POST again with `clear=1` → the seam is called with
  `null`. The `TempData["info"]` flash key is `settings.quiet.flash_saved`
  then `settings.quiet.flash_cleared`.

  has **no** recipient-id parameter — the recipient is always
  `SubjectId(User)`. Assert the action's signature (source/`ActionDescriptor`
  or a reflection pin) has no `recipientId`/`id` binding — a resident cannot
  target another resident's schedule.
- **Pin 3 — kw-l closure witness (the parity pins).** The 15 `settings.quiet.*`
  / `admin.quiet.*` keys are each present **non-empty** in `EnValues`,
  `DeValues`, `FrValues`, `DaValues`. (The existing
  `KnownTranslationKeys_ParityTests` / `KwLRegistryConsistencyTests` auto-extend
  over `AllKeys`; add an explicit pin naming the 15 keys so the M20 closure is
  a first-class assertion, not an implicit one.)
