# M28 U03 — The three `IUserInfoService` seams + implementation + the standing/audit tests

## Context (self-contained)

M28 = **Guardian time limits**: a **guardian** sets a per-child schedule
(hours × days-of-week, Blocked/Allowed polarity) that **gates the child's
whole-platform access** (a sign-out, the `BlockedAccountMiddleware` analog).
This is the **inverse of the M20 quiet lane** (ADR 0121) but on the **GU
guardian surface** (ADR 0028), using the **same pure-evaluator discipline**
(wall-clock-first, ADR 0019). U00 locked the design doc + ADR 0151. U01
created the doc + enum. U02 authored the pure evaluator.

**U03 adds the three additive seams on `IUserInfoService`** (the GU surface,
the ADR 0006-E compatible ADD precedent) + the `UserInfoService` implementation
(the active-link + GlobalAdmin gate, the one audit row on the write, the
strong-consistency read) + the standing/audit/consistency tests. **No
middleware, no Web surface, no kw-l yet.**

**The three seams (the D4 set, pinned in the design doc §2.1):**
- `GetChildTimeLimitAsync(guardianId, childId)` — the guardian's edit-page
  read; gate = active `GuardianLink` ∪ GlobalAdmin; **no** audit row.
- `SetChildTimeLimitAsync(guardianId, childId, schedule?)` — the guardian's
  write; gate = active `GuardianLink` ∪ GlobalAdmin (deny →
  `UnauthorizedAccessException`, Web 404); **one** `AccessAudit` row
  (`Via: Guardian` or `Via: Admin` (G·5), `TargetKind` the child account,
  verb `guardian.time-limit.set`); `null` schedule → delete (the M20
  "clear" idiom); strong consistency.
- `GetActiveTimeLimitAsync(childId)` — the **enforcement** read (child-keyed,
  no guardian gate, **no** audit row) — the middleware's single-row load.

**The gate shape (C-M28·4/C-M28·7):** the write gate is an **active
`GuardianLink`** for (guardianId, childId) **∪ GlobalAdmin** (G·2
deny-by-default, G·5 safety valve); a non-guardian, non-admin gets
`UnauthorizedAccessException` (Web 404 — the GU standing-lane shape,
`SuspendChildAsync` precedent). **The child cannot write their own
schedule** (C-M28·7 — a child subject used as `guardianId` on their own
`childId` is denied).

## Goal

The three additive seams on `IUserInfoService` (the GU surface) + the
`UserInfoService` implementation (the active-link + GlobalAdmin gate, the
one audit row on the write, the strong-consistency read) + the F5-write /
C-M28·4 / C-M28·7 standing + audit + consistency tests. **No middleware,
no Web surface, no kw-l yet.**

## Rules

- **No middleware, no Web surface, no kw-l yet** (U04/U05/U06 own those).
- The three seams are **additive** on `IUserInfoService` (the ADR 0006-E
  ADD precedent — no re-shaping of existing methods).
- The gate is **active `GuardianLink` ∪ GlobalAdmin** (the GU standing
  shape, the `SuspendChildAsync` precedent) — not a new `AccessVia`, not a
  new `AccessAction` (C-M28·5).
- The **write** emits **one** audit row; the **reads** emit **none**
  (the GU audit shape, the `guardian.suspend` / `guardian.unsuspend`
  precedent).
- `null` schedule → **delete** the row (the M20 "clear" idiom, the
  `session.Delete` shape).
- **Strong consistency**: the write is in the caller's session (no
  projection, no cache — C-M28·4, the ADR 0050 `IsSignupOpen` shape).
