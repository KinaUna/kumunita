# M18 · U04 — The head-edit cascade (`UpdateAsync` cascades / re-materializes the series)

**U01 and U02 must be done first** (U01 for the types / fields / expander; U02 so create already materializes the series this unit re-materializes on a rule / `Start` / `End` change). This unit is **Core-only**; the exit gate is `dotnet build Kumunita.slnx -c Debug` + `dotnet exec tests\Kumunita.Core.Tests\bin\Debug\net10.0\Kumunita.Core.Tests.dll`, both green.

## Goal

Extend the **edit** write-lane so that editing a **head** row cascades the text / display / audience fields to all non-deleted siblings, and re-materializes the series (soft-delete old siblings, insert the new set) when the rule itself or the head's `Start` / `End` changes. Land GATE-4. Editing a **non-head** row, or a head with **no** rule, behaves exactly as today (single-row edit — the zero-change branch).

Locked decisions: **D4** (the cascade + re-materialization), **C-M18·4** (author ∪ GlobalAdmin only — the existing `UpdateAsync` standing, unchanged), **C-M18·5** (no new authz surface), **C-M18·8** (the re-materialization's soft-delete of old siblings is the same reversible soft-delete U03's seam uses — a re-materialization is a bulk of `IsDeleted = true` on the old siblings, never a hard-delete).

2. **`src/Kumunita.Core/Events/EventService.cs`** (edit) — in the `UpdateAsync` body, after the existing head-row field application (the text / display / audience / `Modified` stamp), insert the cascade branch:
   - **Resolve the head's current state:** load the row being edited; determine `isHead = row.RecurrenceRule is not null` (the head is the only row with a non-null rule, D3). If **not** a head (or the row has no rule), proceed exactly as today — the existing single-row edit path, **byte-for-byte unchanged** (this is the zero-change branch; a non-head edit never cascades).
   - **If a head:**
     - **Text / display / audience cascade (always, when the head is edited):** apply the new `Title` / `Body` / `Location` / `Capacity` / `Color` / `Audience` / `ReminderEnabled` / `LanguageCode` to **every non-deleted sibling** (`RecurrenceHeadId == head.Id` and `IsDeleted == false`) in the **same transaction** as the head. The head's own `RecurrenceRule` is updated to `request.Recurrence` (or cleared if `request.Recurrence` is `null` / `None` — a "stop repeating" edit).
     - **Re-materialization (only when the rule or `Start` / `End` changed):** if `request.Recurrence` differs from the head's prior rule (by `Recurrence` / `Interval` / `Count` / `Ends`) **or** the head's `Start` / `End` changed: soft-delete **all** existing non-head siblings (`IsDeleted = true` — the C-M18·8 reversible soft-delete, never hard-delete), then call `EventRecurrenceExpander.ExpandRecurrence(head, now: <the same now source U02 used>)` on the **updated** head, and insert the new sibling rows (mirroring U02's persistence shape: fresh `Id`s, `RecurrenceHeadId == head.Id`, `RecurrenceRule == null`, the head's `AuthorId` / `IsDraft` / `GroupId` / `TagIds` / `ImageIds` / `AttachmentIds` copied). The head's own `Id` is **stable** (it is updated in place, never re-created).
     - **Standing is unchanged** — `UpdateAsync` is already author ∪ GlobalAdmin; no `IAuthorizationService` change (C-M18·5).
   - **No** `AccessAudit` row (match the existing edit lane's audit posture — do not add a new one).
