## Goal

Create the **Web surface part 2** of M17: the **`_BookmarkButton`
shared partial** (the "Bookmark" / "Bookmarked" toggle control, rendered
on the **five** target detail surfaces), the **`POST /bookmarks/toggle`**
action (the toggle write lane, the D3 write-lane visibility check,
the D4 idempotency), and the **pinned Web tests**.

**The locked decisions you implement (from the design doc — read §kw-l,
§gate (a), §2.2 (the result-type shapes), §2.3 (the D3 write-lane
visibility check), verbatim):**
- **D4 / F1** — the toggle is **idempotent**: bookmarking the same
  target twice commits **one** row (the unique index is the witness,
  the M9 `convo_uidx_pair` shape); the button reflects "bookmarked"
  on reload. Unbookmarking removes the row; re-bookmarking is a
  fresh `Created` timestamp.
- **D3 / F2** — the write lane re-runs the target's **own** frozen
  `Read` decision **before** the row is created; Deny ⇒ `Refused`
  (the Web layer maps to a **404**, not 403), **no row survives**.
- **C-M17·5 / D5** — the unbookmark control works on a **degraded**
  row (the row is keyed on the owner's own `Bookmark` id, not the
  target's id, so the unbookmark needs no target read at all).

## Deliverables (6 files)

1. `src/Kumunita.Web/Views/Shared/_BookmarkButton.cshtml` — the
   **shared partial** (the **exact** shape below; a small `<form>`
   POSTing to `/bookmarks/toggle` with a hidden `_csrf` + a button
   carrying the `bm.button.bookmark` / `bm.button.bookmarked` key
   depending on the current state):
   - **Inputs**: `string targetKind`, `string targetId` (the closed
     set + the id of the target the button is rendered on).
   - **State**: the button's label is **static** per render (the
     `bm.button.bookmark` key) — the server does **not** query the
     owner's bookmark state on every page load (the D2 / C-M17·2
     pin: the owner's list is a personal read, but the detail view
     does **not** load the owner's bookmark list to decide the
     button's label — the button is a **write** control, the
     toggle's `AlreadyBookmarked` result is the "bookmarked"
     witness). **Exception**: if the page's model already carries
     a `BookmarkState` (e.g. a re-render after a toggle), the
     button's label switches to `bm.button.bookmarked`.
   - **Form**: `<form method="post" asp-controller="Bookmarks"
     asp-action="Toggle" asp-route-kind="@targetKind"
     asp-route-id="@targetId">` with a hidden `_csrf` + a button
     carrying `<kw-l key="bm.button.bookmark">Bookmark</kw-l>` (or
     `bm.button.bookmarked` when the page's model carries
     `BookmarkState == Bookmarked`).
   - **No** JS (the form is a plain POST; the redirect-after-write
     precedent is the reload).

2. `src/Kumunita.Web/Controllers/BookmarksController.cs` (U03's
   file, **extended**) — the **`POST /bookmarks/toggle`** action
   (the **exact** shape below; mirror the U03
   `POST /bookmarks/{kind}/{id}/remove` shape):
   - `[Authorize]` + `[ValidateAntiForgeryToken]`.
   - **Inputs**: `string kind` (the closed set, §2.1), `string id`
     (the target's id).
   - **Owner check**: the actor's `SubjectId` (via
     `KumunitaPrincipal.SubjectId(user)`) is the `ownerId`; a
     non-owner call (a `GlobalAdmin` who is not the owner) is a
     **non-leaky 404** (`NotFoundResult` — the C-M17·2 pin, the
     ADR 0105 "operator has no read standing" precedent).
   - **Write lane**: the seam's `ToggleAsync(ownerId, kind, id,
     session)` is the **sole writer** (the C-M17·1 pin: the
     controller never re-derives access, the seam does the D3
     write-lane visibility check + the D4 idempotency). The
     controller maps the `BookmarkToggleResult.Status`:
     - `Bookmarked` → `RedirectToAction("Index", "Posts",
       new { id })` (or the equivalent for the other four
       surfaces — the "redirect after write" precedent).
     - `AlreadyBookmarked` → `RedirectToAction("Index", "Posts",
       new { id })` (the F1 no-op; the button's label on the
       re-rendered page switches to `bm.button.bookmarked`).
     - `Refused` → `NotFoundResult` (the D3 write-lane visibility
       check failed — the target is not visible to the owner,
       **no** row survives, the Web layer maps to a **404**, not
       403).
     - `Removed` / `NotBookmarked` → not reachable from the
       toggle action (those are the `RemoveAsync` results).
   - **Session shape**: the action opens a **new** `IDocumentSession`
     (the `IUnitOfWork` shape, the M16 `InventoryController`
     precedent) and passes it to the seam's `ToggleAsync` (the
     C3 same-transaction pin — the domain write + any in-session
     audit row commit or roll back atomically).
