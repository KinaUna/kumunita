## Goal

Create the **Web surface part 2** of M37: the **`GET /notes` action** on
the **existing** `NotesController` (the U04 controller — U05 adds the
action, does not create a new controller), the **`/notes` list view**
(the owner's notes, grouped by `TargetKind` + **nested under the
owner's folder tree**, the `pn.list.degraded` label on dangling rows,
the per-row edit / move / tag / delete controls, the tag chips), the
**`pn.*` `kw-l` keys** (× en/de/fr/da into `KnownTranslationKeys` — the
§kw-l list, locked by U00), the **nav entry** (`pn.nav` — the shared
top-nav + the icon rail), and the **pinned parity tests** (the
`KnownTranslationKeys_ParityTests` extension for the `pn.*` keys).

**The locked decisions you implement (from the design doc — read §kw-l,
§2.2, §2.4, §2.5 verbatim):**
- **C-M37·2** — the owner's note list is a **personal read**: a
  **non-owner** (a `GlobalAdmin` included) gets a non-leaky **404** on
  the `GET /notes` list — and that 404 commits **no** `AccessAudit` row
  either (the ADR 0105 "operator has no read standing" precedent). The
  controller's `[Authorize]` is a convenience pre-gate only; the owner-
  check (`SubjectId(user) == ownerId`) is the gate.
- **C-M37·5 / D7** — a note whose target is absent, soft-deleted, or no
  longer visible renders the **generic** `pn.list.degraded` label (a
  closed `kw-l` key) — **no title, no link, no id** — **and the body
  remains visible** to the owner (the D4 "content, not pointer" pin).
  The note controls (edit / move / tag / delete) still work on the
  degraded row.
- **§kw-l** — the `pn.*` keys (the §kw-l list, locked by U00) are
  registered in `KnownTranslationKeys` (× en/de/fr/da), the closed set
  the parity tests pin.
