## Goal

Implement the **folder-tree seam** of `IPersonalNoteService`: replace
the 4 stub bodies (the `NotImplementedException` stubs U02 left) with the
**D6 implementations** — `CreateFolderAsync` (the depth ≤ 2 pin; the
`(OwnerId, ParentId, Name)` unique index is the witness),
`RenameFolderAsync` (the D6 witness), `DeleteFolderAsync` (moves the
folder's notes to the root — `FolderId = null` — the D6 pin; the note
bodies are never lost), `MoveNoteToFolderAsync` (the D6 pin — the note
and the folder are in the same owner's tree). Then the **6 pinned
folder-tree tests** (the §2.5 list's C-M37·6_* tests).

**The locked decisions you implement (from the design doc — read §2.2,
§2.5 verbatim):**
- **D6** — the folder tree is a personal tree, bounded in depth (≤ 2:
  root → child → grandchild), unique in name (the
  `(OwnerId, ParentId, Name)` unique index is the witness). A note's
  `FolderId` is the **owner's** folder id (a note cannot live in another
  resident's folder). A folder's deletion **moves** its notes to the root
  (`FolderId = null`) — the note body is never lost.
- **C-M37·6** — the folder tree is a personal tree, bounded in depth,
  unique in name (the invariant the tests pin).

## Deliverables (2 files)

1. `src/Kumunita.Core/PersonalNotes/PersonalNoteService.cs` — **replace
   the 4 stub bodies** with the D6 implementations:
   - `CreateFolderAsync(string ownerId, string name, string? parentId,
     IDocumentSession session)` — the depth ≤ 2 pin (D6): if
     `parentId` is null, the folder is a **root** folder (depth 1); if
     `parentId` is non-null, the parent must be a **root** folder (the
     parent's `ParentId` must be null — the depth ≤ 2 pin), else
     `FolderCreateResult.Refused` (the depth pin; the Web layer maps to
     400 — the depth is violated). The `(OwnerId, ParentId, Name)`
     unique index is the witness (a duplicate folder name in the same
     owner's tree is a no-op — the M17 `Bookmark` unique-index shape
     re-used).
   - `RenameFolderAsync(string ownerId, string folderId, string newName,
     IDocumentSession session)` — the D6 witness: the folder must belong
     to the owner (the `OwnerId` pin); the `(OwnerId, ParentId, Name)`
     unique index is the witness (a duplicate folder name in the same
     owner's tree is a no-op — the M17 `Bookmark` unique-index shape
     re-used).
   - `DeleteFolderAsync(string ownerId, string folderId,
     IDocumentSession session)` — the D6 pin: the folder must belong to
     the owner (the `OwnerId` pin); the folder's notes are **moved** to
     the root (`FolderId = null`) — the note bodies are never lost; the
     folder row is physically removed (the M17 `Bookmark` physical-
     removal shape). Child folders (depth 2) are **recursively deleted**
     (their notes are moved to the root too — the D6 pin).
   - `MoveNoteToFolderAsync(string ownerId, string noteId, string?
     folderId, IDocumentSession session)` — the D6 pin: the note must
     belong to the owner (the `OwnerId` pin); the folder (if non-null)
     must belong to the **same** owner (the D6 pin — a note cannot live
     in another resident's folder); the note's `FolderId` is set to
     `folderId` (or null for the root).

   **The result types** (from §2.2): `FolderRow(string Id, string Name,
   string? ParentId, int NoteCount)`; `FolderCreateResult(string Status,
   FolderRow? Folder)` with `Status` ∈ {`Created`, `AlreadyExists`,
   `Refused`} (the depth pin — `Refused` when the depth is violated);
   `FolderDeleteResult(int NotesMoved, int FoldersDeleted)` (the D6
   shape — the notes are moved, the folders are deleted).
