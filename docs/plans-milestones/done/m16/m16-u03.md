## Goal

**Extend** the `IInventoryService` + `InventoryService` with the **write lanes**
(create / edit / delete / check-out / check-in), the **standing probes** (D5), and the
**atomic transition** (F1). The write lanes re-check standing **server-side** (the Web
`[Authorize]` is a convenience pre-gate only — F4). The M4 full-interface-first pin
applies: U02 ships the reads; **U03 appends the writes**; a rename or re-scope of a
method after U02 is a **drift event**.

**The locked decisions you implement (from the design doc — read the write-lane +
standing-probe + F1 sections verbatim):**
- **D4 / C-M16·3** — check-out sets `CurrentHolderId` + **appends** an
  `InventoryCheckout`; check-in clears it + **closes** the open record. Records are
  **append-only** (never mutated/deleted). At most **one open checkout per item** — the
  **unique partial index** (U01) on `(ItemId)` where `CheckedInAt IS NULL` is the F1
  witness; a concurrent double-check-out's second commit fails → the loser sees "already
  checked out".
- **D5 / C-M16·4 / C-M16·5** — the standing probe is a **pure server-side probe**
  composing the frozen `IAuthorizationService` "can see it" + `IUserInfoService` role
  probe: **creator ∪ GlobalAdmin** over create/edit/delete; **any member who can see
  it** over a community/shared check-out/check-in; **owner ∪ GlobalAdmin** over a
  private one. **No** new `AccessVia`; the Web `[Authorize]` is a convenience pre-gate
  only.
- **C-M16·2** — every write decision writes exactly one `AccessAudit` row (`TargetKind
  = "inventory"`, `Via Owner/Admin`), in-transaction (C3, the `IDocumentSession`
  overloads), Allow **and** Deny.
