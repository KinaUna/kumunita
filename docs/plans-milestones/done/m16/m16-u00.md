**The [PROPOSED] lock set (from the register — lock these **verbatim**):**

- **D1 — Two documents, one new surface, no new bounded context.** A new bounded context
  `Kumunita.Core.Inventory` with **two documents**: `InventoryItem` + `InventoryCheckout`,
  on a **new `M16DocTypes`** surface (M9/M5 precedent, additive, idempotent, zero
  migrations). The usage history is the `InventoryCheckout` records *inside* the same
  context. *Forbids:* a third "Usage" doc/context; a migration of an existing surface.
- **D2 — Access = the frozen `IAuthorizationService` + an adapter, zero new branch.**
  `InventoryItemToAuditableResource` (the exact M5 `ProjectToAuditableResource` 6-member
  projection; `TargetKind = "inventory"`); every read via `CanAsync(Read)` /
  `CanSeeAsync(Read)`. No new `AccessAction`/`AccessVia`/`Decide()` branch; no new method
  on `IAuthorizationService`. *Forbids:* a new action/via/branch; reading group
  membership for access in Inventory.
- **D3 — Ownership kind is a label, never an access gate.** `OwnerKind` ∈
  {`shared`,`community`,`private`} is a **string** (M5 `KanbanStatuses` shape) driving UI
  grouping + the write-standing breadth (D4) — never a read gate. The list filters
  candidates by `OwnerKind` (a filter, never a gate — C-M3·2); the audience decision is
  unchanged. *Forbids:* `OwnerKind` as an enum; `OwnerKind` deciding access.
- **D4 — Check-out/check-in = an atomic state transition + an append-only record.**
  Check-out sets `InventoryItem.CurrentHolderId` + appends an `InventoryCheckout`;
  check-in clears it + closes the open record. Records are **append-only** (never
  mutated/deleted). At most **one open checkout per item** (a unique partial index on
  `(ItemId)` where `CheckedInAt IS NULL` — the M9 `convo_uidx_pair` shape). *Forbids:* a
  separate usage table/context; mutating a closed record; a second open checkout.
- **D5 — The write standing is a server-side probe, never a new `AccessVia`.** Creator ∪
  GlobalAdmin over create/edit/delete; any member who can see it over a community/shared
  check-out/check-in; owner ∪ GlobalAdmin over a private one. Web `[Authorize]` is a
  convenience pre-gate only. *Forbids:* a new `AccessVia`; Web `[Authorize]` as source of
  truth.
- **D6 — M16 is a core surface, not a lane: no off-by-default toggle.** No admin toggle,
  no `LocaleSettings`-style switch. *Forbids:* an off-by-default toggle.
- **D7 — The close flip is one atomic unit (U06).** `Milestones.cs` M16→done/M17→next;
  `MilestonesTests.cs` re-pinned to `M17_Is_The_Single_InProgress_Milestone` + shipped
  list gains M16 + M18 planned; README Roadmap/Status; `docs/STATUS.md`;
  `docs/ARCHITECTURE.md` value-chain M16 row. All four in the same unit. *Forbids:*
  reordering M17/M18; breaking the pins; flipping one surface and not the others.
- **D8 — No notification lane in M16 (deferred).** Composes only the frozen
  `IAuthorizationService` + `IUserInfoService` over `IDocumentStore`. No
  `INotificationService`, no Wolverine handler, no nudge. The "optionally" is the usage
  history, not notifications. *Forbids:* an `INotificationService` in the composition; a
  Wolverine handler.

- **C-M16·1 — Access = the frozen seam + the adapter** (every read via the frozen
  `IAuthorizationService` over `InventoryItemToAuditableResource`, `TargetKind =
  "inventory"`; `OwnerKind` never an access gate; M16 adds an *adapter*, not a *branch*).
- **C-M16·2 — Every read decision audits, in-transaction** (detail: single-target row;
  list: one aggregate row, `visibleCount`/`hiddenCount`; Allow **and** Deny; C3, the
  `IDocumentSession` overloads).
- **C-M16·3 — Append-only history; atomic transition** (the checkout record set is the
  history; never mutated/deleted; at most one open checkout per item — the index is the
  witness).
- **C-M16·4 — Zero new `AccessAction`/`AccessVia`/`Decide()` branch.**
- **C-M16·5 — Visibility is the Audience; standing is the action** (a resident can *see*
  a shared item; the *standing* is what lets them *act*; the two never leak into each
  other; `OwnerKind` is a filter, never a gate).
- **C-M16·6 — M16 is a standing core surface (no toggle).**
- **C-M16·7 — The close flip is atomic** (D7).

- **FACES F1–F5 + the named trade** (the register's wording): F1 atomic transition
  (unique partial index witness, M9 `convo_uidx_pair`); F2 one `CanSeeAsync(Read)` pass
  + one aggregate row, `OwnerKind` a filter never a gate; F3 the history is the
  append-only records; F4 the write standing is a server-side probe; F5 a standalone
  core surface. **Named trade:** the private-vs-shared write-standing breadth (a broad
  standing over community/shared items vs. an owner ∪ GlobalAdmin standing over private
  ones; the C-M16·5 split keeps visibility always-Audience and action always-standing
  probe).
- **§kw-l key list** (the `inv.*` keys × en/de/fr/da — U04's source of truth): `inv.nav`,
  `inv.list.title`, `inv.list.empty`, `inv.list.ownerKind.shared`, `inv.list.ownerKind.community`,
  `inv.list.ownerKind.private`, `inv.list.filter`, `inv.create.title`, `inv.create.name`,
  `inv.create.ownerKind`, `inv.create.description`, `inv.create.component`, `inv.create.submit`,
  `inv.detail.title`, `inv.detail.currentHolder`, `inv.detail.history`, `inv.detail.edit`,
  `inv.detail.delete`, `inv.detail.checkOut`, `inv.detail.checkIn`, `inv.edit.title`,
  `inv.edit.submit`. (Adjust names to the views as you author them; the **list** is what
  U04 registers — the count/names are locked here so U04 and the parity tests agree.)
- **§gate — the three acceptance tests** (U06 adds them): (a) **closed-loop** (create a
  shared item → a second resident checks it out → in → the history shows exactly one
  checkout); (b) **handoff-authorization-boundary** (a private item is hidden to a
  non-member — list `hiddenCount ≥ 1`, detail is a 404 not a 403; a shared item is
  visible to all members but only the standing actor checks it out — the deny row
  commits); (c) **part-vs-whole-audit-completeness** (the list's aggregate `AccessAudit`
  row commits atomically with any concurrent write — C3; the transition's audit row
  commits atomically with the state change — C-M16·3).
- **§deferred:** the "nudge the owner on checkout" lane (D8); the per-item translation
  lane; the media/attachments-on-items lane; the recurring/reserved check-out lane —
  each "own ADR".
- **§drift-guard — the frozen pins + the drift log:** the frozen seams
  (`IAuthorizationService`, `AccessAction`, `AccessVia`, `Decide()`), the D1–D8
  decisions, the C-M16·* invariants, the §kw-l list, the §gate names. A change to any of
  these after U00 is a **drift event** (record it in the drift log).
