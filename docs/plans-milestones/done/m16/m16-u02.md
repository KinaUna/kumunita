## Goal

Add the `IInventoryService` + `InventoryService` **read lanes** (list by `OwnerKind`
filter + `CanSeeAsync(Read)`; detail + `CanAsync(Read)` with the 404-vs-403 split;
usage-history read), the `InventoryRequests.cs` DTOs, and the
`DependencyInjection.cs` registration — the M5 `IProjectService` read-lane shape. **The
write lanes are U03** (not here).

**The locked decisions you implement (from the design doc — read the read-lane +
composition sections verbatim):**
- **D2 / C-M16·1 / C-M16·2** — every read via the **frozen** `IAuthorizationService`
  (`CanSeeAsync(Read)` list / `CanAsync(Read)` detail) over
  `InventoryItemToAuditableResource`; each decision writes exactly one `AccessAudit`
  row (Allow **and** Deny), in-transaction (C3, the `IDocumentSession` overloads).
- **D3 / C-M16·5** — the list filters candidates by `OwnerKind` (a **filter, never a
  gate** — C-M3·2) + the optional `componentId`; the audience decision is unchanged.
- **D8 / C-M16·6** — the composition is `IDocumentStore` + `IUserInfoService` +
  `IAuthorizationService` only — **no** `INotificationService`, **no** Wolverine
  handler.
- **F2 / F3** — the list is one `CanSeeAsync(Read)` pass with one **aggregate** audit
  row (`visibleCount`/`hiddenCount`); the history read is the append-only checkout
  records ordered by `CheckedOutAt` desc.
