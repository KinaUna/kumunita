# U06 — the **Razor inbox views** (list + empty state + "mark all read") + the **layout bell** (the `_AccountNav` badge + the dropdown)

**Goal:** create the **two Razor views** —
`src/Kumunita.Web/Views/Notifications/Index.cshtml` (the
inbox list + the empty state + the "mark all read" button)
and wire the **layout bell** in
`src/Kumunita.Web/Views/Shared/_AccountNav.cshtml` (the
unread-count badge + the dropdown that links to
`/notifications`) — the **server-rendered** (Razor Pages /
MVC, the ADR 0001 stack pin) shape. **All labels use
`kw-l` keys** (the U07 unit ships the *complete* key set —
U06's views may reference the full set, U07 adds them to
`KnownTranslationKeys.cs`); **all timestamps render through
the `kw-dt` TagHelper** (the ADR 0019 / 0020 pin). **The
bell's poller + dropdown render is U08's** (the `.ts`
module) — U06 ships only the **static markup** (the bell
icon + the badge element + the dropdown anchor) that U08's
TS module will wire.

**Deliverables (closed set):**
- **`src/Kumunita.Web/Views/Notifications/Index.cshtml`**
  (new) — the **inbox view**:
  - **The header:** the `kw-l` key
    `notifications.inbox.title` (the "Notifications" label)
    + the "mark all read" button (a Bootstrap `btn
    btn-outline-secondary btn-sm`, a `<form>` POST to
    `/notifications/mark-all-read`, the `kw-l` key
    `notifications.mark_all_read` label, the
    `[ValidateAntiForgeryToken]` shape — the M5 action-button
    precedent).
  - **The list:** a Bootstrap `list-group` (the M4 / M5
    list-view shape), one `list-group-item` per
    `Notification` row, each rendering:
    - **The kind badge:** a `badge text-bg-...` (the
      per-kind color — the `post.reply` / `group.post` /
      `event.rsvp` / `event.reminder` / `report.filed` /
      `report.assigned` / `report.resolved` / `todo.assign`
      badge classes, the `notifications.kind.{kind}` `kw-l`
      keys for the badge text).
    - **The body:** the `Notification.Body` (the UGC
      snippet, the sender's authored language — the ADR
      0018 pin, the `kw-l` key
      `notifications.inbody.body` label prefix).
    - **The timestamp:** the `kw-dt` TagHelper on
      `Notification.Created` (the ADR 0019 / 0020 pin —
      the recipient's effective tz / format).
    - **The read-state:** a `text-muted` class when
      `Notification.ReadAt != null` (the "read" visual
      state, the M5 read/unread precedent).
  - **The empty state:** when
    `ViewModel.Notifications.Count == 0`, a Bootstrap
    `alert alert-info` (the M4 / M5 empty-state shape) with
    the `kw-l` key `notifications.empty_state` (the "No
    notifications yet" label).
  - **The count:** the `ViewModel.Count` displayed in the
    header (the "N notifications" label, the `kw-l` key
    `notifications.count`).
- **`src/Kumunita.Web/Views/Shared/_AccountNav.cshtml`**
  (modified) — **add the bell** (next to the existing
  account-dropdown):
  - **The bell icon:** a Bootstrap `btn btn-link position-relative`
    (the `text-decoration-none` shape), with a
    `<span class="badge text-bg-danger rounded-pill
    position-absolute top-0 start-100 translate-middle"
    id="notifications-badge" hidden>0</span>` (the
    unread-count badge, **hidden** by default — U08's TS
    module will populate it).
  - **The dropdown anchor:** a `<a>` (or a
    `data-bs-toggle="dropdown"` trigger) linking to
    `/notifications` (the inbox view, the U05 route) —
    the M2/M3/M4 nav-dropdown idiom.
  - **The ARIA attributes:** the `aria-label` (the `kw-l`
    key `notifications.bell.label`, the "Notifications"
    label), the `aria-live="polite"` on the badge element
    (the screen-reader shape, the M5 nav precedent).
  - **No inline `<script>`** (the U08 TS module wires the
    poller — the ADR 0031 tsc-only / no-dependency pin;
    U06 ships only the *static* markup).
- **Nothing else.** No `.ts` module (U08), no `site.css`
  rules (U08), no `kw-l` keys (U07), no tests (U09), no ADR.
