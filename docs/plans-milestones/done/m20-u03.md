### 2. `src/Kumunita.Core/Notifications/NotificationService.cs` (the gate + helper)

**Insert the gate in `EmitAsync`** (the 9-arg overload) at the D4 point — after
the D7 email-kind gate (`EmailEnabledForAsync` resolves "email enabled") and the
`event.reminder` carve-out, and **before** the `IMailerStage` stage:

```csharp
// (M20 — the quiet-hours gate, D4) — consulted AFTER the inbox row is stored
// and AFTER the D7 email-kind gate, BEFORE the email is staged. A quiet
// recipient keeps the inbox row (D7) but the email is DEFERRED, not dropped
// (D1): mark the row EmailDeferred and return — no IMailerStage.StageAsync.
if (await QuietNowForAsync(session, recipientId, now: DateTimeOffset.UtcNow, ct).ConfigureAwait(false))
{
    notification.EmailDeferred = true;
    return notification;   // inbox row stored (D7); email held (D1)
}
```

**Add the `QuietNowForAsync` private helper** (D3/D4 — the effective-zone
resolver + the pure-evaluator call; U02's evaluator is pure, so this helper is
the *only* place the zone is resolved):

```csharp
/// <summary>D4 — the quiet gate's resolver: load the recipient's
/// NotificationQuietSchedule (U02), resolve the ADR 0019 effective zone
/// (Profile.TimeZone override → LocaleSettings.DefaultTimezone → UTC floor) via
/// IUserInfoService + ILocalizationService, and call the PURE
/// QuietScheduleEvaluator.IsQuietNow (D3). A null schedule → false (the floor,
/// C-M20·3). Never throws into the caller's transaction (a resolution failure
/// degrades to "not quiet" — the email flows, the safe default).</summary>
private async Task<bool> QuietNowForAsync(
    IDocumentSession session, string recipientId, DateTimeOffset now, CancellationToken ct);
```

Implement: `GetQuietScheduleAsync` → if `null` or `!Enabled` return `false`;
else resolve `TimeZoneInfo` (the ADR 0019 chain — `TimeZoneInfo.FindSystemTimeZoneById`
on the resolved id, falling back to `TimeZoneInfo.Utc` on a bad id) → call
`QuietScheduleEvaluator.IsQuietNow(schedule, now, zone)`. **The inbox row is
never skipped** (C-M20·1) — the gate returns *after* `session.Store(notification)`.

**The deferred idempotency key** (the D4/§6.2 form) is a `const`/`static` on
the service so U04's flush reuses the *same* form (do **not** inline it in
U04):

```csharp
/// <summary>D4 — the deferred-email idempotency key form. Distinct from the
/// emit-time key (notification:{kind}:{source-id}) so the outbox dedup (F10)
/// does not collide; the flush job (U04) stages the held email under this key,
/// so a cleared email is delivered exactly once (C-M20·4).</summary>
public static string DeferredKey(string kind, string sourceId) =>
    $"notification:{kind}:{sourceId}:deferred";
```

## Pinned tests (add to the `Kumunita.Core.Tests` `NotificationService` test file)

- **GATE-1 pin (C-M20·1 — defers email, never inbox)** —
  `EmitAsync_QuietRecipient_StoresRow_Deferred_NoEmail`: with a quiet schedule
  for the recipient (via `SetQuietScheduleAsync`, U02) + an active instant,
  `EmitAsync` stores the `Notification` row (`EmailDeferred == true`), stages
  **no** email (assert the `IMailerStage` was **not** called), and the row is
  returned (not `null`).
- **GATE-3 pin (C-M20·3 — floor = never quiet)** —
  `EmitAsync_NoSchedule_StagesEmailAsBefore`: a recipient with **no**
  `NotificationQuietSchedule` row goes through the pre-M20 path (email staged,
  `EmailDeferred == false`).
- **Not-quiet path** — `EmitAsync_NonQuietWindow_StagesEmail`: a schedule that
  is *not* active at the instant stages the email normally (`EmailDeferred ==
  false`), and the deferred key is **not** used.
- **Quiet gate is after the D7 kind gate** —
  `EmitAsync_KindDisabled_Still_SuppressesEmail`: a recipient whose
  `NotificationPreference.KindsEnabled` omits the kind still suppresses the
  email (the existing D7 gate is untouched; the quiet gate does not widen it).
