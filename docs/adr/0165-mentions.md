# ADR 0165 — M36: @mentions — a cross-surface `@<resident>` reference token: type a resident's directory display name after an `@`, the platform resolves it against the frozen M2 directory and (a) notifies the mentioned resident on that surface (a new mention kind per surface, the ADR 0076 D2 "follow-on lane") and (b) renders the name as a link to the resident's directory page; additive on the frozen surfaces, no new bounded context

Status: Accepted
Date: 2026-10-12
Amends: **0076** (the ADR 0076 D2 `post.mention` kind — **reserved, not wired**, "mention detection is a follow-on lane" — is now **wired** on the community post + reply surface, and the **closed `NotificationKinds` vocabulary gains six sibling mention kinds**, one per other in-scope surface; the `NotificationPreference` / `NotificationSubscription` / `EmitAsync` seams are **untouched** — the mention emitters ride the frozen `EmitAsync`), **0077** (the admin-lane kinds stay a separate lane — the mention kinds are resident-facing, opt-OUT, and trail the resident-facing kinds in `Known`), **0005** (the `kw-l` closed registry — the seven mention kinds' `notifications.kind.*` + `notifications.preference.*.label` + `notification.*.subject` + `notification.*.body` keys join it, all four languages), **0015** (the TagHelper + curated-registry discipline the new `kw-l` keys follow), **0025 / 0031 / 0033** (the RC / WYSIWYG Markdown renderer — a mention is a **post-render pass** over the frozen `MarkdownRenderer` output, not a new Markdown construct; the one-renderer pin is preserved), **0013** (the group-post lane — `group.post.mention` rides the frozen ADR 0013 membership read seam), **0039** (the pages lane — `page.mention` rides the frozen `PageService` write lane), **0054** (the M4 events lane — `event.mention` rides the frozen `EventService` create lane), **0067** (the M5 to-do lane — `todo.mention` rides the frozen `ProjectService.CreateTodoCommentAsync` lane), **0105** (the M9 messaging lane — `message.mention` rides the frozen `MessagingService.SendAsync` lane), **0012** (the announcements surface — `announcement.mention` rides the frozen `AnnouncementService` publish lane), **0023** (the M2 directory — the `IDirectoryService` read seam M36 resolves display names against is **frozen, not re-shaped**), and **0006** (the `IAuthorizationService` / `IAuditableResource` surface — **no new adapter**, no new `AccessAction`, no new `AccessVia`; a mention is a *personal read*, the ADR 0076 D3 shape).

## Context

The roadmap has shipped the full resident surface — posts, group posts, pages, events, projects, to-dos, announcements, messaging, a directory of residents. And M6 (ADR 0076) shipped the **shared-awareness lane**: the inbox + the email, with a closed, code-owned kind vocabulary and a per-kind settings toggle. But ADR 0076 D2 deliberately left one kind **reserved, not wired**:

> `PostMention` = `"post.mention"` — **reserved, not wired** (the constant + the `kw-l` keys exist; no M6 emitter calls it — **mention detection is a follow-on lane**).

The "follow-on lane" is **M36**. A resident composes a post, a reply, a page, an event, a to-do comment, a group post, an announcement, or a direct message and wants to reach a specific neighbor — *"@Ada can you bring the projector?"* — rather than broadcast to everyone. Today the platform has no notion of "this is *for* Ada": the body is inert text, Ada is not told, and the name does not link anywhere. M36 adds the **`@<resident>` mention**: a reference token where a resident types `@` followed by another resident's **directory display name**, and the platform

1. **notifies the mentioned resident** on that surface (a new mention notification kind, one per in-scope surface, riding the frozen M6 `EmitAsync` — inbox row + best-effort email, the ADR 0076 D5 shape), and
2. **renders the name as a link** to the resident's directory page (a post-render pass over the frozen `MarkdownRenderer` — the one-renderer pin is preserved).

This is the single most-requested missing verb on a community platform: it is how a neighbor reaches *another neighbor by name* without leaving the thread. It reuses everything M6 already built (the kind vocabulary, the settings toggle, the email + inbox lanes, the quiet-hours gate, the sample-suppression gate) — it only adds the **detection** (who was mentioned) and the **render pass** (link the name), and extends the closed kind vocabulary with the per-surface mention kinds.

**Roadmap order (recorded here, per the sign-off gate):** M35 (kiosk, ADR 0164) is `StatusDone`; **M36 is the single `StatusNext`**; there is no `M37` — M36 is the **new last milestone** on the roadmap (M35 was the last, M35·11; M36 supersedes it as the new terminal milestone — the `MilestonesTests` "no in-progress" pin is re-pinned to "M36 is the single in-progress, and the last").

## Decision

**D1 — M36 is an additive delta on the frozen surfaces: one shared Core module, per-surface emitters, a Web render pass. No new bounded context, no new doc, no new doc-type surface, no EF migration.**
M36 **creates** the one new shared Core module `Kumunita.Core.Mentions` — the **pure** `MentionTokens` parser (a static helper, the `UgcSnippets` / `KanbanStatuses` shape — no docs, no deps) + **one service** `IMentionService` (a plain store-composing service over the **frozen** `IDirectoryService` read seam — the M34 "derived, not captured" shape, the M13 `IUsageAnalyticsService` / M25 `IStorageMetricsService` read-seam precedent). It **extends** the **existing** per-surface services with a mention-emitter step in each write lane (the `PostService` / `PageService` / `EventService` / `ProjectService` / `AnnouncementService` / `MessagingService` create-and-persist lanes — **additive**, the frozen method signatures + audit rows **untouched**), and **adds** a Web render pass over the **frozen** `MarkdownRenderer`. It creates **no** new bounded context, **no** new doc, **no** new doc-type surface, **no** new index, **no** EF migration. *Forbids:* a new bounded context for mentions, a new `Mention` doc (a mention is **derived** — the `@token` + the directory match — not captured), a new doc-type surface, or an EF table for a mention.

**D2 — The reference token is `@` + a resident's directory `DisplayName`, matched against the frozen M2 directory. No new `Profile` field, no new handle.**
The mention is `@<DisplayName>` — the resident's display name exactly as it appears in the M2 directory (`/directory`). Detection resolves each `@` token against the directory's **non-blocked** residents (the frozen `IDirectoryService` read) and collects the matching resident ids, **excluding the content's author**. A token that matches **no** resident is inert (plain text). A token that matches **two or more** residents (a shared display name) is **also inert** — ambiguous = no mention, never a guess (the M2 directory "show-everyone" pin: every non-blocked resident appears, so a display name is not guaranteed unique, and a mention must not silently notify the wrong resident). *Forbids:* a new `Profile.Handle` / `Profile.Slug` field (a schema delta), a username system, an email-address mention, an `@all` / `@everyone` broadcast mention (a named deferral), or resolving a token to a *specific* resident when the display name is ambiguous.

**D3 — The `post.mention` reserved kind is now wired, and six sibling kinds join the closed vocabulary — one per in-scope surface.**
ADR 0076 D2 reserved `post.mention` as the follow-on lane; M36 wires it on the **community post + reply** surface and adds **six** new `NotificationKinds` members, one per other in-scope surface: `group.post.mention` (group post + reply), `page.mention`, `event.mention`, `todo.mention` (to-do comment), `announcement.mention`, and `message.mention`. All seven are **resident-facing, opt-OUT** (in the `post.reply` / `group.post` posture — **not** in `NotificationKinds.OptInKinds`; a fresh install with no preference row fires them). They trail the resident-facing kinds in `NotificationKinds.Known` (the closed, ordered set — the settings page + the `kw-l` key table both enumerate `Known`, so adding a kind is a one-line `Known` entry + the `kw-l` delta, D7). The **admin-lane** kinds (`account.signup` / `account.verified`) stay a separate lane (ADR 0077). *Forbids:* a resident-authored kind string, an enum-backed kind, reusing a single `post.mention` kind for every surface (the closed-vocabulary discipline says each surface's mention is its own kind — a resident's settings toggle for "mention me on events" is distinct from "mention me on pages"), or an unregistered kind reaching the inbox.

**D4 — The mention idempotency key is per-recipient: `notification:{kind}:{contentId}:{recipientId}`.**
ADR 0076 D4 pins the key shape as `notification:{kind}:{stable-source-id}` and dedups on the **key alone** (not per-recipient) — the single-recipient kinds (`post.reply`, `message.new`) are safe because the recipient is deterministic. A mention is **multi-recipient**: one body may mention three residents. The recipient id is therefore **part of the key** (`:{recipientId}`) so each mentionee stores their own inbox row + gets their own email, while a re-emission of the same (content, recipient) pair is still a no-op (D4 / F10 preserved). *Forbids:* a mention key that omits the recipient id (which would suppress the second mentionee's row), or a key that includes a non-stable value (a timestamp, a GUID regenerated per call).

**D5 — A mention is a *personal read*, not an `AccessAction` decision. Zero new `AccessAction` / `AccessVia` / `Decide()` branch / `IAuditableResource` adapter.**
A mention notification is **the mentioned resident's own data** (the ADR 0076 D3 shape, verbatim): the emitter stores an inbox row + stages a best-effort email for the recipient — no `IAuthorizationService` call, no audit row for the mention itself (F7). The **render pass** links `@Ada` to `/directory/{adaId}` — that link rides the **frozen** M2 directory gate on click (the detail surface runs its own `ContactVisibility` decision), so a mention link **grants no access** to the source content beyond what the resident could already see, and reveals nothing the resident could not already read (the M8 search / M12 iCal "a link is not a grant" posture). *Forbids:* a new `AccessAction`, a new `AccessVia`, an `IAuditableResource` adapter for a mention, or an `AccessAudit` row emitted *by* the mention emission.

**D6 — The render pass is a no-op for an unresolved `@` token, and a mention is a post-render pass — not a new Markdown construct.**
The one-renderer pin (ADR 0025 / 0031 / 0033) is preserved: `MarkdownRenderer.RenderHtml` is **unchanged**. The mention is a **post-render pass** (`MentionRenderer` in the Web boundary) that runs *after* the Markdown → HTML render, scanning the rendered body for `@<DisplayName>` tokens that resolve (via the same `IMentionService` directory read the controller resolved once) to a non-blocked resident and rewriting **only those** to `<a href="/directory/{id}">@Ada</a>`. Every other `@` (a lone `@`, an `@` inside a code span, an unresolved name, an ambiguous name) stays **plain text** — the pass never invents a link and never changes Markdown grammar. The pass is **idempotent** (it matches `@name` text, not `href`), so an already-linked mention is not double-wrapped. *Forbids:* a new Markdown token / grammar rule for mentions, a change to `MarkdownRenderer.RenderHtml` / `renderPreview` / `dom-to-markdown`, an `@` link that targets a blocked or ambiguous resident, or a mention that renders inside an existing `<a>` / `<code>` element.

**D7 — The `kw-l` closed registry gains the seven kinds' full key set × en/de/fr/da; the `post.mention` toggle goes from reserved/disabled to enabled.**
Every new user-visible string M36 introduces is a `KnownTranslationKeys` entry present, **non-empty, in all four** languages (en/de/fr/da), pinned by `KwLRegistryConsistencyTests` + `KnownTranslationKeys_ParityTests` (the M6 U07 / M34·11 closed-set precedent). Per mention kind: the **four** keys `notifications.kind.{kind}`, `notifications.preference.{kind}.label`, `notification.{kind}.subject`, `notification.{kind}.body` — **seven kinds × four keys = 28 new keys × four languages** (the `post.mention` kind + preference labels already exist from M6's reserved set — only its `notification.post.mention.subject` / `.body` templates are new). The `Views/Notifications/Preferences.cshtml` **removes** the `post.mention` reserved/disabled special-case (the "coming soon" badge) so the toggle is a normal opt-OUT switch, and the six new kinds' toggles render. *Forbids:* a mention `kw-l` key present in only some languages, a `KnownTranslationKeys` entry that is empty, or leaving the `post.mention` toggle disabled (the lane it reserved is now wired).

**D8 — Detection runs on the **publishing** write lane, not on draft-save; a mention in a draft body is inert until the content is made visible.**
ADR 0037 drafts are author-only, excluded from every feed, and a resident may never publish a draft. A mention in a **draft** body must **not** notify (a resident is not told about content that may never be seen by anyone else). So M36's emitters run in the lane that makes the content **visible** — the **publish** seam for the draft-capable surfaces (post / group post / announcement — the ADR 0037 author-only idempotent publish lane) and the **create** lane for the non-draft surfaces (page / event / to-do comment / message). The `EmitAsync` call is in the **same transaction** as the domain write (the ADR 0076 D5 / C3 shape: one `SaveChangesAsync` commits the content + the inbox row + the outbox envelope atomically). *Forbids:* a mention emission on a draft-save (a premature notification), or a mention emission that commits in a different transaction than the content write.

**D9 — Core stays HTTP-free + Wolverine-free; the shared module is a plain store-composing read over the frozen directory seam.**
`Kumunita.Core.Mentions` (the `MentionTokens` pure helper + the `IMentionService` / `MentionService`) is a plain store-composing service (the `AddTransient<IMentionService>` shape, the M13 `IUsageAnalyticsService` / M25 `IStorageMetricsService` precedent). `IMentionService.ResolveAsync` composes the **frozen** `IDirectoryService` read seam to map display names → resident ids (a read, not a decision). There is **no** `HttpClient` in Core (ADR 0006-D), **no** Wolverine handler, **no** outbound channel — the only outbound channel is the frozen M6 email lane (`IMailerStage`, already present). *Forbids:* an `HttpClient` in Core, a Wolverine handler for mention detection, or a mention resolver that bypasses the frozen directory read seam.

**D10 — The six-member close flip lands in the final unit; M36 is the new last milestone.**
The `Milestones.cs` / README / `STATUS.md` / `ARCHITECTURE.md` / `MilestonesTests.cs` / `WhatsNew.cs` six-member close flip lands in the final unit (the M35-U10 / M34-U08 precedent). The `WhatsNew.cs` registry gains one new entry (newest-first, the next `0.x.0` row) naming M36 + ADR 0165. **M36 is the new last milestone** — the close flips `M36` from `StatusNext` to `StatusDone` and promotes **no** successor (the `MilestonesTests` pin changes from "no in-progress milestone" (M35's terminal state) to "`M36` is the single in-progress, and the last" — the M34-U08 "last milestone, no successor" framing, re-applied). *Forbids:* closing M36 without the `WhatsNew.cs` entry, or promoting a phantom `M37`.

## Consequences

- **The ADR 0076 D2 "follow-on lane" is now real.** The reserved `post.mention` constant + the reserved `kw-l` keys + the reserved settings toggle all go from "coming soon" to wired on the community post + reply surface — the six sibling kinds extend the same shape to the other seven surfaces. M6's closed-vocabulary discipline (D2), the `EmitAsync` writer (D4/D5/D7), the quiet-hours gate (ADR 0121), the sample-suppression gate (ADR 0078), and the per-kind settings toggle (the `Notifications/Preferences` surface) are **all reused unchanged** — M36 adds a detection step + a render pass + the kind/`kw-l` delta, nothing else.
- **A resident can now reach a neighbor by name on any content surface.** `@Ada can you bring the projector?` in a post, a reply, a page, an event, a to-do comment, a group post, an announcement, or a message → Ada gets an inbox row + (unless quiet / disabled) an email, and everyone reading sees `@Ada` as a link to Ada's directory page.
- **The closed `NotificationKinds` vocabulary grows by six.** `Known` gains `group.post.mention`, `page.mention`, `event.mention`, `todo.mention`, `announcement.mention`, `message.mention` (and `post.mention` goes from reserved to wired). Every consumer that enumerates `Known` (the settings page, the `kw-l` key table, the per-kind inbox badges) picks up the new kinds automatically — the `kw-l` parity tests are the drift guard.
- **The directory is a resolution input, not a gate.** M36 reads the frozen `IDirectoryService` read seam to map display names → resident ids. It does **not** change the directory, does **not** add a `Profile` field, and does **not** re-run the directory's `ContactVisibility` decision for the mention (that decision still runs, on click, on the directory detail surface the link points at).
- **A mention is inert where it cannot be resolved.** An unknown name, an ambiguous name, a blocked resident, and the author themselves all yield **no** notification — the pass degrades to plain text, never to a wrong or a self-notification.
- **Zero new dependency, zero new npm package, zero build step.** The render pass is plain TS over the existing `client/lib` module (the ADR 0031 tsc-only pin) or a server-side pass in the `MarkdownRenderer` boundary — no mention-parsing library, no `@linkify` dep.
- **M36 is the new last milestone.** M35 (kiosk, ADR 0164) was the last (M35·11); M36 supersedes it. The roadmap's terminal state after M36's close is "all done, no in-progress."
